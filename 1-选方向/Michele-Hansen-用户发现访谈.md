# Michele Hansen：产品未定型前的用户发现访谈

> 来源层级：**辅源**，不覆盖赫兹主源（ADR-0001）。
> 文章：Michele Hansen，*[Customer Interview Script: Discovery Phase (i.e. before you've built anything)](https://deployempathy.substack.com/p/customer-interview-script-discovery-phase-i-e-before-you-ve-built-anything-415336)*
> 用法：在候选方向阶段还原用户最近一次真实流程，取得问题、替代方案与参与者证据；不把访谈伪装成产品推销。
> 配套：`.claude/skills/direction-validator/references/user-contact-playbook.md`、`1-选方向/MRR-Unlocked-验证想法.md`

## 一句话概念

用户发现访谈先核验创始人以为存在的问题是否真实发生，并用用户自己的流程、替代方案、成本和参与者重建问题；它不以推销 Demo、收集“会不会用”或凑固定访谈人数为目标。

## 访谈证据速查

| 要取得的证据 | 该问什么 | 用于判断 |
|---|---|---|
| 最近一次真实流程 | “上一次发生时，能带我走一遍吗？” | 触发、步骤与交接是否存在 |
| 频率与痛感 | “多久发生？最烦/代价最大的部分是什么？” | 是否值得优先解决 |
| 当前替代 | “现在怎么处理？试过哪些工具？为何没用下去？” | 现有承接与切换阻力 |
| 已付成本 | “花了什么时间、钱或返工成本？” | 付费时刻与损失 |
| 参与者 | “谁使用、选择、批准、付款或受影响？” | 买家、决策者与阻力 |
| 理想变化 | “如果能改一处，会改哪里？” | 待验证的结果承诺，不直接等于功能 |

```text
先还原最近一次真实流程
→ 追问人工步骤、替代方案与成本
→ 找最痛交接和相关角色
→ 取得最小充分证据
→ 才展示验证型承接物并观察行动
```

## 可复用细节

### 1. 先问过去，不问预测
- 从“最近一次发生是什么时候、当时怎样完成”开始；追问信息从哪里来、谁接手、哪里等待或返工。
- 不先问“你会不会用这个产品”；这只会得到礼貌预测，不是行为证据。
- 对用户的描述先复述确认，再继续问“然后呢、为什么、上次的后果是什么”，不要把自己的产品解释塞进对方回答。

### 2. 把问题拆成流程而非功能
- 记录触发、完整步骤、人工动作、工具、失败点、外部参与者和交接。
- “在用 Excel”只是线索；继续问 Excel 承接什么、在哪一步失效、为何不换现有工具。
- 使用者、发起者、决策者、付款者和受影响者可能不同，B2B 里不可混为一人。

### 3. 以最小充分证据决定下一轮
- 不把作者“至少 5 人、可能 10–20 人”的研究建议作为本项目门槛；它适合追求模式饱和的较完整研究。
- 对中国出海新手的早期微实验，2–3 条独立、合资格且含近期场景、替代或代价的回复，可能已足够收窄假设或决定下一步。
- 新回复不再改变 `go / narrow / watch / reject` 时停止；回复高度分散时优先收窄人群、场景或任务，而不是机械凑人数。

### 4. 研究邀请要降低陌生人防备
- 说明研究对象、预计时间与感谢方式，明确这不是销售邀请；不把研究邀请偷换成推销。
- 录音、屏幕共享或保存资料必须单独征得同意；公开观察不自动获得私聊、发帖或收集数据权限。
- 音频、文字异步交流、流程走查和脱敏样例是逐步增强的证据，不把屏幕共享或长时访谈设为初次交流的门槛。

## 防止误用

- 访谈证明的是问题与流程，不自动证明付款；付款仍需真实价格、预订、订金或付款实验。
- 作者给出的 45–60 分钟、礼品卡和 5–20 人建议是其语境案例；本项目用最小充分证据，而非固定人数。
- 不把“魔法棒”答案直接写成功能路线图；先用近期行为、替代方案和成本核验。
- 触达受限、帖子被过滤或无人回复首先是渠道/信任问题，不自动等于没有需求。
