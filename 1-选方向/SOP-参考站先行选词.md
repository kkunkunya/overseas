# SOP：参考站先行选词

> 2026-08-23 起默认。旧的「先从任务假设扩词」已归档，见 [`归档-SOP-垂直选词人机闭环.md`](归档-SOP-垂直选词人机闭环.md)。  
> 术语见 `CONTEXT.md`；量/KD 与选词顺序见 ADR-0015。  
> 项目 skill：`vertical-keyword-loop`（`.pi/skills/`，`scope: project`）。

## 一句话

```text
目标领域
  → 多模型找付费参考站（Markdown + 超链接）
  → 你看站，并导出 Semrush
  → Agent 用导出写成功根源并挖词
  → 3 个核心词 + 10–15 个长尾
  → Instagram / Reddit / TikTok 反查需求
  → 做出海付费 App
```

- **Agent**：并行调用多个模型找参考站，整理成可点击清单；拿到你导出的 Semrush 后再写成功根源和词表。不编造流量、反链、月搜或 KD，也不自己登 Semrush 硬拉。
- **你**：点开站点看 Title、Description 和付费入口；对准备深挖的域名，从 Semrush 导出流量、反向链接、流量占比和自然关键词，交给 Agent。
- **产品形态**：出海 App / 订阅或明确付费。电商和纯广告站只作背景，不进正式参考清单。

## 1. 找参考站

你给出目标领域后，Agent 用当前能用的多个模型（Grok、ChatGPT、Cursor 等）各自列站，再合并去重。

优先收：订阅、买断、应用内付费墙，或能看清谁在付钱的产品站。Semrush 意图可标 **C（Commercial）** 的词所指向的站优先。

交付：一份带超链接的 Markdown 清单。你直接点开看。

## 2. 你看站，并导出 Semrush

对准备深挖的站，你自己看 Title、Description 和付费入口。SEO 概况和挖词所需数字，从 Semrush 导出后交给 Agent，不要让 Agent 自己猜或改用别的工具顶上。

每个准备深挖的域名，导出这些就够：

| 导出什么 | 用来判断什么 |
|----------|----------------|
| 流量规模 | 这个域名大概有多强 |
| 反向链接 / 引用域 | 外链底子 |
| 流量占比（搜索 / 直接 / 社媒 / 推荐） | 成功是靠 SEO、品牌还是别的渠道 |
| 自然关键词（量、KD、意图） | 从站挖词；C 优先 |

Agent 用导出写清：流量多少、反链多少、各渠道占比，以及「钱怎么收、人从哪来」。说不清就还没读完导出，不要开始挖词。

## 3. 从站挖词

只从导出覆盖、且你确认过的付费参考站往外挖。量/KD/意图只读这份导出。

- 重点找**搜索量大、KD 较低**的词。新手优先 **KD < 50**；更高不是禁区，只是竞争通常更强。
- 偏门：该领域已经打出名堂的**品牌词**，常常量不小、竞争却低于同义大词，用来观察用户怎么搜这个品类，不是去抢别人的品牌首页。

交出 **3 个核心关键词** 和 **10–15 个长尾词**，每个词写清量、KD（导出里没有就写 No data）、来源站、为何适合做成付费 App。

## 4. 社区反查再做产品

仿照参考站，去 Instagram、Reddit、TikTok 等平台看真人怎么说、现在怎么凑合、卡在哪一步、会不会为结果付钱。再结合词表决定产品，并持续维护。

## 每轮检查清单

- [ ] 参考站清单可点击，且优先是付费/订阅站
- [ ] 你已看过 Title、Description 和付费入口，并导出了准备深挖站的 Semrush
- [ ] 成功根源写在导出上：流量、反链、流量占比
- [ ] 3 个核心词 + 10–15 个长尾有量/KD 或明确 No data
- [ ] 品牌词只作品类参考，不作为去抢别人首页的理由
- [ ] 社区反查后再定产品，不从空想扩词开做
