# 第一步作战卡：从词到值得做的产品

> 当前主线：先找到一个真实搜索入口并取证它背后有一项值得交付的用户结果；随后直接做能兑现核心任务的可用 MVP，上线观察并迭代。热词抢占不做。
>
> 这张卡只负责选词找方向和产品首版入口；实际产品开发在独立产品仓库完成。

## 全流程

```text
外部信号
→ 客户任务与当前替代
→ 词群与竞品产品链
→ 窄产品承诺
→ 可用 MVP + SEO/GEO 最小包
→ 上线、分发、8–12 周观察与迭代
```
```

“选词”不是从一堆高量词里挑一个，而是找到一段已经发生的用户任务：用户主动用什么语言找帮助，现有页面给了什么，仍缺哪一个结果，我们是否能以更窄的方式交付它。

## 阶段 A：找到可承接的词和任务

### 1. 从有体感的信号起一个候选

写下 3–8 个线索：自己熟悉的场景、用户抱怨、已有产品、人工服务、社区重复提问，或用户正在搜索的表达。

每个线索先写成：

```text
谁：
触发时刻：
他想完成什么：
现在怎样凑合：
```

这一步由 `direction-validator` 判断：它是一次性搜索任务、重复工作流，还是免费结果之后可能继续发生的工作。

### 2. 用词群和竞品验证任务是否存在

对最有希望的线索，用 `treg-research` 取少量外部事实，再由 `vertical-keyword-loop` 收束。

```text
同一任务的搜索表达
→ 同一条件下的前排页面
→ 用户在页面上马上得到什么
→ 页面把人带向内容、报告、账户、真人服务还是支付
→ 当前替代仍没有解决什么
```

本轮只保留最多 3 个词群。每个词群最终只写六句话：

1. 用户在什么时刻要完成什么；
2. 现在使用什么替代；
3. 前排实际交付了什么；
4. 还没被顺畅承接的是哪一步；
6. 用户可能如何完成、回访、分享或付费，及竞品已有的变现线索。

词量、趋势、难度、排名词、反链或竞品价格只在改变其中某一句时记录。不要按指标逐行排词，也不要把竞品清单当结论。

### 3. 从竞品页面决定产品基调

只看同一任务下的前排独立站，沿下面这条链走一遍：

```text
入口页 → 即时结果 → 内容/样例/相关页 → 价格或回访
```

由此做三个取舍：

| 看到的情况 | 产品决定 |
| --- | --- |
| 用户必须输入、操作或生成才能完成 | 首版做能直接交付结果的小产品，首屏先放结果。 |
| 用户只是需要理解、比较或选择 | 首版做有明确结论、样例和边界的解释/比较页。 |
| 竞品免费结果已经很完整 | 不复制基础工具；只测试结果后的未承接步骤。 |
| 竞品靠多年内容、真人供给、品牌或庞大目录成立 | 作为竞争背景，不放进首版范围。 |
| 竞品的付费发生在更多结果、保存、批量、人工解释或持续任务之后 | 只把其中与我们产品结果相连的那一项留作付费假设。 |

内容不是先铺出来的。现在只写帮助用户完成核心结果所需的样例、步骤、边界和 FAQ；多个用户反复提出同一个相邻问题后，才为它加一张独立页面。

### 阶段 A 的出口

写出一个可兑现的窄承诺：

> 对 `{谁}` 在 `{触发时刻}`，输入 `{什么}` 后，得到 `{具体结果}`；它不替代 `{现实决策/专业服务/其他边界}`。

此时结论只有四种：

| 结论 | 什么时候用 |
| --- | --- |
| `go` | 用户任务、现有替代缺口、可交付结果和潜在行动都具体。进入阶段 B。 |
| `narrow` | 只有更窄的人群、场景或结果成立。收窄后重跑本阶段。 |
| `watch` | 缺一条会改变产品决定的事实。只写唯一复查条件。 |
| `reject` | 用户不需要额外结果，或没有资源可承接的付费/行动路径。停止。 |

## 阶段 B：做可用 MVP 并上线观察

`go` 直接交给 `seo-site-blueprint`。在独立产品仓库做一个用户愿意使用、能兑现核心任务的首版，并同步落实 SEO/GEO 最小包：

```text
明确的客户任务、SERP/竞争与承诺
→ 可用 MVP（核心任务真能完成）
→ 初始 HTML、索引角色、内链、robots、sitemap
→ 上线、首批分发与真实使用
→ 8–12 周观察窗
→ 两轮针对最早瓶颈的调整
→ 加码、收窄或归档
```

首版不能是只收集口头兴趣的粗糙概念页，也不因“最小”而不兑现用户任务。登录、复杂套餐、后台和未被任务要求的 Agent 能力留到真实使用显示需要时再加。短期无排名不淘汰；按收录、展示/出词、排名、有效点击/任务完成、回访/分享和收入依次判断。

## 领域与 skill 关系

```text
【路由层】ask-overseas
    判断当前最早缺口，选择唯一下一步

【方向层】direction-validator
    外部信号 → 客户任务、替代、产品形态

【取证层】treg-research
    搜索 / 竞品 / 社区 / 引用 / AI 来源 → 可复核事实

【选词找方向层】vertical-keyword-loop
    词群与竞品事实 → 可承接任务、窄承诺、go/watch/narrow/reject

【产品首版层】seo-site-blueprint → 独立产品仓库 → seo-readiness-audit
    已取证任务 → 可用 MVP、SEO/GEO 最小包 → 可公开的产品资产

【发现与放大层】distribution-link-loop / geo-source-loop
    已上线任务页 → 外部发现、第三方推荐、AI 来源资产

【复盘层】product-growth-review
    8–12 周自有数据 → 最早瓶颈 → 单一调整 → 加码/收窄/归档
```

`kb-ingest` 是材料归档支路：只在有文章、视频、帖子或课程需要存进知识库时使用，不参与产品决策。
