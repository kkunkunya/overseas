# 第一步作战卡：从参考站到值得做的付费 App

> 当前主线：先找到目标领域里已经靠订阅或明确付费活下来的参考站，人看懂它的 SEO 和商业逻辑，再收 3 个核心词和 10–15 个长尾；随后去海外社区反查需求，做能兑现任务的可用 MVP。热词抢占不做。
>
> 这张卡只负责选词找方向和产品首版入口；实际产品开发在独立产品仓库完成。

## 全流程

```text
目标领域
→ 多模型找付费参考站
→ 你看站，并导出 Semrush
→ 用导出写成功根源，再挖 3 个核心词 + 10–15 个长尾
→ Instagram / Reddit / TikTok 反查需求
→ 可用 MVP + SEO/GEO 最小包
→ 上线、分发、8–12 周观察与迭代
```

不要从任务假设或脑暴词表起手。先看谁已经收了钱，再学它的词和获客结构。电商站和纯广告站只作背景。

## 阶段 A：找到可学的站和可做的词

### 1. 写出目标领域

一句话写清你想做的领域，以及为什么像出海付费 App（订阅、买断或明确付费意愿），而不是电商或广告站。

交给 `vertical-keyword-loop`。Agent 用多个模型列出参考站，整理成带超链接的 Markdown。

### 2. 你看站，并导出 Semrush

对准备深挖的站，自己看 Title、Description 和付费入口。流量、反向链接、流量占比和自然关键词从 Semrush 导出后交给 Agent。没有导出就停，不要让 Agent 改用别的数顶上。

### 3. 从成功站收词

只读这份导出，从确认过的付费站往外挖：

- 搜索量大、KD 较低；新手优先 KD < 50
- 该领域成名产品的品牌词当作品类参考，不去抢别人的品牌首页
- 交出 3 个核心关键词和 10–15 个长尾词；导出里没有的量/KD 写 No data

### 4. 社区反查后再定产品

仿照参考站，去 Instagram、Reddit、TikTok 看真人怎么凑合、卡在哪一步、会不会为结果付钱。任务或形态仍不清时才用 `direction-validator`。

### 阶段 A 的出口

- 一份可点击的付费参考站清单，且准备深挖的站已有 Semrush 导出
- 3 个核心词 + 10–15 个长尾，带来源和量/KD（或 No data）
- 一句产品方向：对谁、在什么时刻、输入什么、拿走什么结果

| 结论 | 什么时候用 |
| --- | --- |
| `go` | 付费逻辑清楚，词有量、可做，社区能对上需求。进入阶段 B。 |
| `narrow` | 只有更窄的人群、场景或结果成立。收窄后重跑本阶段。 |
| `watch` | 缺一条会改变产品决定的事实。只写唯一复查条件。 |
| `reject` | 没有可学的付费站，或词做不成付费 App。停止。 |

## 阶段 B：做可用 MVP 并上线观察

`go` 直接交给 `seo-site-blueprint`。在独立产品仓库做一个用户愿意使用、能兑现核心任务的首版，并同步落实 SEO/GEO 最小包：

```text
明确的客户任务、SERP/竞争与承诺
→ 可用 MVP（核心任务真能完成）
→ 初始 HTML、索引角色、内链、robots、sitemap
→ 上线、首批分发与真实使用
→ 8–12 周观察窗
→ 两轮针对最早瓶颈的调整
→ 加码、收窄或归档
```

首版不能是只收集口头兴趣的粗糙概念页，也不因“最小”而不兑现用户任务。登录、复杂套餐、后台和未被任务要求的 Agent 能力留到真实使用显示需要时再加。短期无排名不淘汰；按收录、展示/出词、排名、有效点击/任务完成、回访/分享和收入依次判断。

## 领域与 skill 关系

```text
【路由层】ask-overseas
    判断当前最早缺口，选择唯一下一步

【选词找方向层】vertical-keyword-loop
    付费参考站 → 人审 SEO/商业逻辑 → 3 核心词 + 10–15 长尾

【取证层】treg-research
    搜索 / 竞品 / 社区 / 引用 / AI 来源 → 可复核事实

【方向层】direction-validator
    已有站和词之后，还原客户任务、替代、产品形态

【产品首版层】seo-site-blueprint → 独立产品仓库 → seo-readiness-audit
    已取证任务 → 可用 MVP、SEO/GEO 最小包 → 可公开的产品资产

【发现与放大层】distribution-link-loop / geo-source-loop
    已上线任务页 → 外部发现、第三方推荐、AI 来源资产

【复盘层】product-growth-review
    8–12 周自有数据 → 最早瓶颈 → 单一调整 → 加码/收窄/归档
```

`kb-ingest` 是材料归档支路：只在有文章、视频、帖子或课程需要存进知识库时使用，不参与产品决策。

细则见 [`SOP-参考站先行选词.md`](SOP-参考站先行选词.md)。旧的从任务扩词剧本已归档。
