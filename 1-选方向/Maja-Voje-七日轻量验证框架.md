# Maja Voje：七日轻量验证框架

> 来源层级：**辅源**，不覆盖赫兹主源（ADR-0001）。
> 文章：Maja Voje，*[My 7-Day Business Idea Validation Framework](https://knowledge.gtmstrategist.com/p/7-day-business-idea-validation-framework)*
> 用法：将“愿景 → 可接近首批人群 → 单一承诺 → 测试版 → 行为复盘”压缩为短循环；七天和作者样本量不是项目硬门槛。
> 配套：`1-选方向/MRR-Unlocked-验证想法.md`、`1-选方向/Michele-Hansen-用户发现访谈.md`

## 一句话概念

验证不必先完成一套漫长研究流程或开发完整产品：从已有洞察选出一个可接近的早期客户画像（ECP）和单一、即时价值承诺，做出诚实标注的薄 Beta，让真实人使用，并以实际行为决定下一轮收窄什么。

## 轻量循环

```text
已有经验 / 公开市场线索
→ 选 ECP：急痛 + 付费可能 + 可接近
→ 定一个低时间到价值的承诺
→ 对比当前替代，写出为什么现在要换
→ 做验证型 Beta 或页面
→ 在合适渠道诚实发布
→ 记录使用任务、重复使用、主动返回与付费行动
→ 收窄 ECP / 用例 / 承诺后进入下一轮
```

## 可复用细节

### 1. 愿景是起点，不是证据
- 创始人的经验、技术变化或公开市场观察可以提供要探索的方向，但不代替用户行为。
- 不为宏观分析、传统访谈数量或固定投资额设虚构门槛；当前问题决定当前最小实验。

### 2. 用 ECP 取代宽泛目标市场
早期客户画像需要同时满足：

| 判断 | 含义 |
|---|---|
| 急痛 | 任务需要现在解决，不是遥远愿望 |
| 付费可能 | 有预算或有足够代价值得付费 |
| 可接近性 | 创始人当前能理解、接近并获得真实反馈 |
| 可形成证明 | 使用后可能形成案例、评价或可复用的结果 |

对中国出海新手，**可接近性**与痛点同样是筛选条件；市场再大、但无法进入或无法理解的人群先放 `watch`。

### 3. 一个窄承诺，尽快得到第一次价值
- 最好的早期用例是具体、可立即执行、低时间到价值的任务，不承诺“解决整个业务”。
- 比较用户现有替代：DIY、模板、人工服务、外包、现有工具或忍受问题；明确为什么这条承诺在时间、投入或质量上更好。
- 产品轨可与发现轨并行，但只做为当前假设服务的薄能力，不按完整路线图累积功能。

### 4. 测试版要诚实、克制地发布
- Beta 可以先发布；明确它是测试版，不用正式产品的声量或保证过度炒作。
- 选择目标 ECP 已出现的渠道；当前阶段不必为了规模而全量触达。
- 作者拥有成熟受众，使用 LinkedIn 软发布；其“100–300 测试者”适合观察多个 AI 使用模式，**不是本项目早期的固定指标**。

### 5. 行为比称赞强
记录的不是“用户说好不好”，而是：

| 行为 | 说明 |
|---|---|
| 输入真实任务并完成结果 | 初步价值 / 使用证据 |
| 多轮追问、重复使用 | 用例适配与即时价值 |
| 主动要求恢复、回来继续使用 | 早期依赖 / 留存线索 |
| 留联系方式、预约、询价、预订或付款 | 更强的商业证据 |

用这些行为找出“在哪个任务上意外好用”和“最常见的真实用例”，再收窄下一轮，而非用泛泛赞美扩张功能。

## 与项目规则的边界

- “7 天”是作者的个人节奏，不是截止日期；本项目采用最小失败实验与最小充分证据。
- 先做 Beta 不等于先做完整产品；遵循 `验证型并行开发`，每项能力必须对应最高风险假设与停止条件。
- 公开发帖是可选分发 / 招募路径；待用户提供自身经验后再沉淀具体发帖规则，不能照抄作者 LinkedIn 受众打法。
- “有人说愿付”仍不等于付款；后续以真实价格与行动入口验证。
