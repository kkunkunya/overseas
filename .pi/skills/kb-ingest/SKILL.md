# kb-ingest / 把资料整理进知识库

本知识库是**查阅库**（AGENTS.md）：笔记层（顶层 6 目录）放二手提炼，`原文/` 等是可检索材料工具箱。本 skill 只负责把新资料**提炼成笔记层的结构化笔记**，让 AI 以后能按步骤、关键词、术语检索到，并与**当前路径**及其他材料交叉引用（ADR-0005）。

## 一条直线

```text
接收资料 → 归步 → 定层级 → 提炼笔记 → 落盘 → 更新索引 → 提交
```

## 1. 接收资料

拿到的是一手素材原文（字幕/逐字稿/文章正文/帖子），不是别人整理好的摘要。先完整读一遍，不跳读。同时记下：

- **来源**：作者 + 标题 + 链接（YouTube URL / 博客 URL / X 推文链接 / 书名页码）
- **形态**：视频 / 文章 / 帖子 / 课程 / 播客 / 书
- **作者与存放**：是否已有 `原文/` 历史包作者、还是新外部材料（见步骤 3）

## 2. 归步

判断这份资料属于 6 步哪一步，按 AGENTS.md 的 6 步定义：

| 步 | 目录 | 主题 |
|---|------|------|
| 1 | `1-选方向/` | 找方向、需求挖掘、卖空气验证、人群/词、定价验证入口 |
| 2 | `2-建站开发/` | 建站、技术栈、AI 写代码、部署 |
| 3 | `3-SEO获客/` | SEO、关键词、内页、收录、外链基础 |
| 4 | `4-流量放大/` | 社媒、外链放大、投流、获客渠道 |
| 5 | `5-变现支付/` | 定价、Stripe/PayPal、提现、转化设计、防薅 |
| 6 | `6-复盘增长/` | 复盘、心态、增长漏斗、数据迭代 |

**跨步资料**：归到**主主题**那步，在笔记里点名其他步的交叉点。例：Marc Lou「10 个获客渠道」含 pSEO（属 3）和定价（属 5），但主主题是获客渠道 → 归 `4-流量放大/`，笔记内点名交叉。

**没有对应步**：资料与出海知识库 6 步都无关 → 不归档，告诉用户为什么不放进来。

## 3. 定存放（无主源等级）

- **默认（几乎所有新资料）** → 进**笔记层**对应步骤目录。标 `材料源：作者 + 出处`（可写「工具箱材料」），**不要**用「辅源 vs 主源」暗示等级。Marc Lou、Greg、YC、Viking、未署名 PDF、小耳朵等全属此类。
- **`原文/` 历史包** → 仅当用户明确要求把某作者原文扩进 `原文/N-步骤/`（现主要为赫兹 227 篇固定包）。文件名保留「编号-标题」格式；不批量改名。新篇进 `原文/` 前先问用户。

材料措辞按 `CONTEXT.md`「权威与来源」：点名作者便于检索；**来源 ≠ 执行优先级**；冲突时以当前路径 + 亲测裁决（ADR-0005）。**禁止**在新笔记写「以赫兹为准 / 主源对接」。

## 4. 提炼笔记

按 `references/note-template.md` 的结构写。**提炼，不堆字幕**——一份视频字幕几千字，笔记目标 200–400 行内、可被 AI 一眼定位。六个固定段落：

1. **来源头**：材料源（作者）+ 标题 + 链接 + 用法（归哪步、对接当前路径哪一环）
2. **一句话概念**：这资料的核心主张，一两句
3. **速查表 / 流程图**：要点一表览或流程框图
4. **可复用细节**：每个要点展开成可直接照做的动作
5. **与当前路径/其他材料交叉**：表格列「资料观点 ↔ 相关材料或路径要点 ↔ 关系（一致/互补/冲突/补洞）」——**多源对照，无等级**；无对应就写"补洞"
6. **防止误用** + **可检索关键词**

**判断：新建笔记 vs 并入已有**：
- 资料是独立一篇/一部 → 新建笔记文件
- 资料只是给已有笔记补一个案例/数据点 → 编辑已有笔记，加一节或一行，不新建
- 资料太薄（只有一两个点）→ 不建笔记，只把要点写进 CONTEXT.md 术语条目或已有笔记

## 5. 落盘

- 文件名：`作者-主题.md`（如 `Marc-Lou-冷邮件验证第一客户.md`、`Greg-Isenberg-Reddit趋势找方向.md`）。作者名用英文/拼音，主题用中文短词。
- 路径：`N-步骤/作者-主题.md`
- 落盘前 `read` 确认目录下无同名/同主题笔记，避免重复。

## 6. 更新索引

落盘后同步三处索引（**漏一处就检索失效**）：

1. **该步 `_本步导航.md`** 的「我整理的笔记」列表加一行：`- [文件名](文件名.md) — **材料**：一句话描述`（作者名可写进描述）。不要用「辅源」暗示低人一等。
2. **`CONTEXT.md`**：资料引入了新术语，或与已有术语**等价/同构**（如"sell before build = 卖空气验证"）→ 新增术语条目，点名出处。无新术语就跳过。
3. **`README.md`**：6 步表格的「笔记」列若该步之前是"（待补）"，现在有了第一篇 → 更新列；「原始链接」区加资料出处。已是多笔记的步骤只更新导航即可，不必每次改 README。

## 7. 提交

```bash
git add -A && git commit -m "添加 <作者> 材料笔记：<主题1>/<主题2>..." && git push
```

提交信息列出新文件 + 改的索引。**提交前 `git status` 看一眼**——避免把工作区里无关的未提交改动一起带进来（`git add -A` 会全加）。发现无关改动，告诉用户有哪些顺带改动，让其确认是保留还是拆分。

## 不做什么

- **不建产品代码**：本库是查阅库，不写 frontend/部署代码（AGENTS.md）。资料里提到的代码片段是案例，进笔记当例子，不另起项目。
- **不把单一作者当教主（含赫兹）**：多材料冲突时写明差异，由当前路径 + 亲测取舍（ADR-0005）；不默认「赫兹压一切」或「新 PDF 压一切」。
- **不堆字幕原文**：逐字稿进笔记要提炼；完整字幕太长不利于检索，除非用户要求存底稿（底稿另存 `-英文底稿.md` 附件文件，主笔记只放提炼）。
- **不批量改 `原文/`**：历史原文层不动（AGENTS.md）。
- **不过度设计笔记**：六段结构是脚手架——没有交叉点就写"补洞"一行；没有速查表就放流程图。别为凑段落灌水。

## 何时用

- 用户丢来视频字幕/逐字稿、文章、帖子、课程笔记说"加进知识库"/"归档"/"整理进来" → 用本 skill
- 用户说"这个视频/这篇文章很好，存下来" → 用本 skill
- 用户只是问知识库里某内容、或要基于已有资料做选方向/搜索机会/增长判断 → **不用**本 skill，走 `ask-overseas` / `direction-validator` / `vertical-keyword-loop` / `research`
