# seo-readiness-audit

先证明搜索引擎能发现、读取和正确归类页面，再讨论排名。按 URL 角色逐项审计，不把技术正确误当作排名保证。

```text
页面角色 → 初始 HTML → 可访问性/规范 URL → 抓取与索引 → sitemap → 内链 → GSC/Bing 证据
```

## 1. 建立审计范围

列出本轮核心 URL、目标任务和页面角色。要排名的页面必须可访问、可抓取、可索引、能从站内浅层抵达并列入 sitemap；公开但不排名的页面保持可抓取以让 `noindex` 生效；敏感页以权限保护。

## 2. 从服务器返回的内容开始

对核心页面检查服务器初始 HTML，而不仅是浏览器渲染后的 DOM：主体是否直接包含核心任务、页面承诺、必要说明与链接。关键内容只在客户端 JavaScript 跑完后出现时，标为阻塞，改为 SSR、SSG、预渲染或其他服务器可见输出。

同时检查：

- 页面返回可访问的成功状态，规范 URL 唯一且 canonical 指向正确版本；
- title、description、单一 H1 与页面任务一致，首屏能进入核心功能/答案；
- 无意外登录墙、空壳表单、循环跳转或重复页；
- 结构化内容、内链、示例与 CTA 确实服务用户任务，不为堆关键词而存在。

## 3. 对齐抓取、索引与站点地图

```text
robots.txt 管是否抓取；noindex 管抓到后是否进索引。
```

若目标是公开页不出现在结果中，允许爬虫访问并读取 `noindex`；不要用 robots 阻断它。sitemap 只列希望参与排名的规范 URL：可访问、可抓取、可索引、非跳转、非重复。检查每个索引页至少有一条语义内链，sitemap 不是发现页面的替代品。

## 4. 连接实际搜索证据

上线后用 GSC 与 Bing Webmaster 查看 sitemap、抓取、索引覆盖、错误和查询数据。出现无展示/流量归零时，先分辨：页面是否可访问 → 是否抓到 → 是否进索引 → 是否匹配意图/页型 → 才讨论竞争、体验与外链。

输出：

```text
阻塞上线：
影响收录/理解：
影响承接体验：
可后置观察：
每项证据、责任位置与复查方式：
```

**完成判据**：核心 URL 的角色、初始 HTML、规范 URL、抓取/索引设定、sitemap 与内链均有可观察证据；问题单按最早阻塞环节排序。
