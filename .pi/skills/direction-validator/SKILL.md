# direction-validator

先确定要验证哪一种生意，再决定找搜索证据、还原工作流或做最小行动实验。

```text
增长入口 → 人群与任务 → 路线 → 最高风险假设 → 最小反证 → 灯色
```

## 1. 选择路线

从用户原话、真实讨论、现有替代和触发时刻中，先写 `谁 × 什么场景 × 要完成什么任务`，再选一个路线：

| 路线 | 优先证明什么 | 下一步 |
|---|---|---|
| SEO 资产 | 用户主动搜索、SERP 可由独立页面承接、存在变现线索 | `vertical-keyword-loop` |
| Workflow SaaS | 有重复或高风险的完整工作，当前替代失败，存在切换和付费时刻 | 工作流证据卡与最小反证 |
| 混合式楔子 | 免费即时任务能带来重复的后续工作 | 先验证即时任务，再观察后续交付 |

搜索量弱不自动淘汰 Workflow SaaS；社区热度也不自动证明 SEO 机会。不同路线不放在一张总分表里比较。

## 2. 测最高风险，不用研究代替决定

列出 3–5 条可被推翻的假设，为每条标商业影响与证据不确定性。优先测试最高的一条：

```text
若对 {人群} 在 {场景} 提供 {输入→结果 / 价格 / 触达}，
则会出现 {可观察行动}。
```

先设本轮范围：最多深查几个候选、什么行动算支持、什么结果触发 `watch/narrow/reject`。新资料不能改变结论时停止继续搜集。

## 3. 取得路线对应的最小证据

Workflow SaaS 或混合式楔子用 [工作流证据卡](assets/workflow-evidence-card.md) 记录：

```text
触发 → 输入 → 当前完整步骤 → 输出/交接 → 当前替代与摩擦
→ 谁承担损失 → 谁买单、何时付费 → 最小反证
```

从真实社区、评论、产品、人工服务或访谈取得原话与流程。没有实际打开的内容只记线索；需要登录态或版规时用用户 Chrome 真实核验。触达应在规则允许、用户授权的范围内进行；细节需要时读取 [许可式调研](references/user-contact-playbook.md)。

具体工作、当前替代失败、可触达入口与商业时刻同时成立，才认为承接有机会。“更漂亮/更智能”不构成可验证缺口。

## 4. 灯色与交接

| 结论 | 条件 | 交接 |
|---|---|---|
| `go` | 路线、工作/搜索任务、最小承接和商业信号已成立 | 明确测试价格或行动时进 `mvp-validation`；需要实现时进入相应产品/搜索流程 |
| `watch` | 缺一项关键证据 | 写唯一复查条件 |
| `narrow` | 只有更窄任务或交接被证实 | 保留它重新取证 |
| `reject` | 工作不具体、替代不痛、不可触达或无商业理由 | 记录最早失败证据 |

用户决定最终方向与对外动作。

**完成判据**：路线、最高风险假设、最小反证与唯一下一步已写清；SEO-first 候选已交给 `vertical-keyword-loop`，不维护第二套选词流程。
