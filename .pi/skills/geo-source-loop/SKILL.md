# geo-source-loop

从一个真实用户问题追到 AI 现有答案依赖的来源，再判断缺哪一个能完成任务、可被引用的产品或事实资产。

```text
真实用户问题 → AI/搜索现有来源 → 来源解决了什么 → 仍缺什么结果 → 自有产品或事实资产 → 引用与任务完成观察
```

## 1. 从问题反推来源

选一个用户会直接问 AI 的具体问题。先写清用户要完成的结果、现有答案为什么不够，以及这次来源研究会改变哪个产品或页面判断。需要实时数据时交 `treg-research`：调用对应 AI response / mention 或搜索端点，再用 Google/Bing 和真实来源页核验。

只记录 AI/搜索现有来源给出的具体工具、样例、比较、事实或限制，以及它仍未交付的结果。一次回答或提及只能告诉我们“现在看见了什么”，不能替代用户使用、收入或长期引用证据。

## 2. 从来源缺口决定资产

先选能完成用户任务的核心产品页，再按它确实缺少的事实补一项资产：

| 缺口 | 可补资产 |
| --- | --- |
| 用户需要输入后获得结果 | 工具或产品页 |
| 用户需要判断自己是否适用、怎样使用或边界在哪里 | 真实样例、案例、比较或限制说明 |
| 用户需要外部信任和发现 | 与任务匹配的第三方榜单、测评或案例机会 |

每项资产写清它新增了什么用户结果或可核验事实，并内链到核心任务页。没有新增结果或事实的页面不进计划。

## 3. 筛选外部引用机会并观察

只争取能把同一类用户带到同一张任务页的第三方文章、榜单、测评或案例。需要查竞品引用来源时交 `treg-research`，再打开来源页核验它为什么推荐、链接落到哪里、是否与任务匹配。

上线后按链条观察：用户从传统搜索或 AI 来源进入 → 是否完成任务 → 是否保存、询价或付费。AI 是否提及只是来源观察，不是优化目标。

输出一张来源资产图：

```text
用户问题 → 现有来源交付的结果 → 未被解决的一步
→ 我们要交付的结果 → 需要补的页面或第三方机会 → 观察行动
```

**完成判据**：每个目标 AI 问题都有可验证的来源记录、来源已交付和仍缺的结果；下一项工作是一张能补这个结果的页面或一个具体第三方机会。
