# geo-source-loop

AI 答案通常以传统搜索索引和少量可用网页为上游。先找清 AI 为回答一个真实问题会检索什么、相信什么，再补能完成任务和可引用的来源资产。

```text
目标 AI 问题 → 真实检索词/来源 → 搜索前排资产 → 自有事实缺口 → 第三方推荐机会 → 引用与点击观察
```

## 1. 从问题反推来源

选一个用户会直接问 AI 的任务问题，而不是泛泛追求品牌被提及。观察 AI 的检索/思考过程、引用页或回答中出现的搜索表达；再到 Google/Bing 查这些表达的 SERP、页型与来源。

记录：目标用户问题、AI 改写的检索词、传统搜索前排、现有引用页提供的具体事实/样例/工具、日期与地区。一次回答或引用是线索，不是稳定流量承诺。

## 2. 规划可引用的自有资产

按任务分工建设：

| 资产 | 作用 |
|---|---|
| 工具/产品页 | 用输入→结果完成用户任务 |
| 教程、案例、比较、限制说明 | 提供可被搜索和 AI 理解、核验和引用的事实 |
| 社区内容 | 获取反馈、用户语言和传播，不替代可长期引用页面 |
| 外部榜单/测评 | 可能形成第三方推荐，需与任务匹配 |

每项自有资产写清独有样例、真实输入输出、适用条件、限制、更新责任和到核心任务页的内链。没有独有事实或任务价值的“最佳工具”改写页不进入计划。

## 3. 筛选外部引用机会并观察

只争取与用户问题、目标任务页和来源语境一致的第三方文章、榜单、测评或案例。链接可抓取性与编辑价值按 `distribution-link-loop` 的三层检查；外部收录成本必须和预期传播/发现/可能权威相称。

上线后分开观察：传统搜索展示与点击、AI 是否引用、AI 引用是否带来合资格访问、访问者是否完成任务。传统搜索基础与产品承接缺失时，先补最早缺口，不靠购买收录或大量空内容掩盖。

输出来源资产图：

```text
AI 问题 → 检索词 → 前排来源 → 用户需要的证据/结果
→ 我们已有资产 → 缺口 → 下一个自有页或第三方机会 → 观察指标
```

**完成判据**：每个目标 AI 问题都有可验证的检索/来源记录；自有资产与任务页分工清楚；下一项工作是一个具体资产或机会，不是泛泛“做 GEO”。
