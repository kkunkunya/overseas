# seo-site-blueprint

把已取证的客户任务与产品承诺，变成一套能承接同类任务、也能被搜索引擎理解的可用 MVP 合同。

```text
已取证的客户任务与承诺 → 页面任务 → 主题树/内链 → 页面 brief → 可用 MVP 首版顺序
```

## 1. 先按任务拆站，不按字面词堆页

读取上游的目标国家/语言、词群、SERP/竞争、客户任务、窄承诺与变现线索。首版直接兑现核心任务；真实使用、回访和收入在上线后的观察窗验证。为每个候选页回答：

```text
用户带着什么任务进入？
首屏如何准确承诺？
在这页完成什么结果或理解什么下一步？
为什么不能由父页或另一页完整替代？
```

同一任务的近义词、拼写变体和相近长尾合在一页；用户目标、流程、结果或 SERP 页型不同才拆页。不能说明独立任务和独有价值的页面，不进首版索引集合。

## 2. 画主题树与页面角色

用 `核心任务页 → 子任务页 → 场景/问题页` 组织页面，并标注父子内链与相关内链。内链同时服务用户下一步和爬虫对主题层级的理解；不把所有链接堆回首页。

给每个 URL 标一个角色：

| 页面角色 | 搜索处理 |
|---|---|
| 要获取搜索流量的工具、内容、比较、目录页 | 可抓取、可索引、列 sitemap、从浅层内链抵达 |
| 公开但不应参与排名的登录、筛选、重复或过渡页 | 允许抓取以读取 `noindex`，不列 sitemap |
| 用户数据、账单、后台 | 权限控制；可用 robots 降低无价值抓取，但不把 robots 当安全边界 |

## 3. 给首版页面写 brief

每页输出以下最小合同：

```text
页面/规范 URL：
用户任务与词群：
页型与首屏承诺：
核心输入 → 结果（或答案）：
Title / 单一 H1：
H2/H3 子问题：用途、场景、步骤、优势、限制、FAQ：
主要 CTA：
父页 / 子页 / 相关内链：
索引角色：
GEO 来源价值：可验证的样例、案例、比较、限制或工作流事实：
首版必须做 / 真实使用后再做：
```

功能先让用户完成任务，文本让搜索引擎与首次访问者理解任务、用法和边界。字数、关键词密度和模板词频只能提示人工复核，不能反过来决定页面内容。

## 4. 定首版发布顺序

首版只保留：一个能兑现主承诺的核心页、支撑其理解/信任的必要内容、最少的相邻任务页，以及这些页面间的内链。将登录、复杂套餐、运营后台、大规模程序化页和未验证语言版本放进“稍后验证”栏。

**完成判据**：有一张页面地图；每个首版页都有独立任务、页面 brief、内链与索引角色；首版范围能解释为何足以承接目标 SERP。
