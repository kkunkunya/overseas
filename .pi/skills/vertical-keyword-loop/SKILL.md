# vertical-keyword-loop

把“一个可能的词”收成资源够得着的用户任务。指标用来排序，真实 SERP、场景、付费线索与用户判断才决定是否投入。

```text
兴趣场景 → 种子词群 → SERP/量/KD/变现取证 → 短名单 → 场景还原 → 灯色
```

## 1. 从任务找词

先写 `谁 × 场合 × 要完成的任务`，再收集 5–15 条英文搜索短语，标明来源（用户经验、竞品、自动补全、Trends、公开讨论）。优先研究已形成付费、人工替代或长期讨论的旧需求中，仍未被前排顺畅承接的一步。

兴趣让人能长期理解和维护场景，但不替代需求证据。市场按任务、竞争、支付与语言承接能力选择，不预设某一国家必然更好。

## 2. 对候选做最小取证

每个准备进短名单的词群记录目标国家/语言、日期，以及：

- **SERP**：主词和 2–5 个任务修饰词的前排、页型、强弱、广告、功能和价格；SERP 决定应做工具、内容、目录还是其他形态。
- **量/难度/趋势**：写厂商和性质（实数、降级线索或 `No data`），不编造、不跨工具精确横比。
- **竞争与商业**：点开 3–5 个结果，看定价、付费时刻、页面承接与具体可赢缺口；“更好看/更智能”不是缺口。

默认数据调用走 **treg**：找词时用其 DataForSEO Keyword Suggestions / Google autocomplete；对人工筛过的 6–12 个任务词，按目标国家、语言、设备取 Google SERP，再合并调 Keyword Overview + Bulk KD 获取量、CPC、趋势与 KD。每轮先声明词数、预算和停止条件；treg 返回的是第三方线索，不替代真实 SERP 判断。

只在当前问题需要时追加调用：SERP 页型或 AI/视频/图片/PAA 会改变承接方案 → Google advanced SERP；不清楚用户是找工具、比较还是购买 → Search Intent；竞品已明确、想找其词群/主力页/交集或新切口 → Keywords for Site、Relevant Pages、Domain/Page Intersection、SERP Competitors 或历史 SERP。它们用于缩小一个具体缺口，不用于把竞品数据库全量导出。

用户能打开目标 SERP、前 3–5 个竞品和趋势页时，复读这些真实页面与插件读数。需要真人语言或实际流程时，按目标人群所在处经 treg 对 Reddit / TikTok / YouTube / Instagram / X / Threads 取小样本帖子、视频或少量强相关评论，再用 Chrome 复读关键原帖、版规与上下文；社区热度本身不构成需求结论。大批量、定时抓取或 dataset 导出才考虑 Apify。

## 3. 短名单与场景

最多保留 3 个词群。每项交付：任务一句话、量/KD/趋势、SERP 摘要、竞争切口、初步变现、未知项与灯色建议。

对准备建议 `go` 的一个主词，用 1–3 个实操演示或等价一手材料还原：

```text
输入 → 当前步骤 → 输出 → 最痛的一步 → 现在如何凑合
```

需要固定格式时读取 [短名单](assets/keyword-shortlist.md) 与 [场景卡](assets/scene-card.md)。用户能口述流程，才进入建站蓝图讨论。

## 4. 灯色与交接

| 结论 | 含义 | 交接 |
|---|---|---|
| `go` | 场景、SERP 承接、商业线索与窄于头名的承诺同时成立 | `seo-site-blueprint`，再做能兑现核心任务的可用 MVP |
| `watch` | 一项关键证据不足 | 写唯一复查条件 |
| `narrow` | 需求存在，但人群、任务、市场或页型太宽 | 收窄后重新取证 |
| `reject` | 当前资源下没有可赢切口、商业理由或长期投入意愿 | 记录最早失败闸门，回种子池 |

用户拍板最终结论。

**完成判据**：短名单不超过 3 项；每项有诚实的量/难度字段、SERP/商业证据和灯色；`go` 有场景说明与一句窄于头名的承诺。
