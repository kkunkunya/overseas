# distribution-link-loop

产品是入场券，分发让合资格用户看见它。外链不是报告里的 URL 数，而是与具体任务页匹配的传播、发现和编辑性引用机会。

```text
任务页 → 用户/作者在哪里 → 竞品来源拆解 → 机会筛选 → 小范围分发/争取收录 → 记录行动与引用
```

## 1. 先确认要带去哪里

每次只选一个已经可用的核心任务页。写清：谁会在什么情境下使用、完成什么结果、为什么值得分享/引用、页面是否可抓取可索引。空壳页先回 `seo-site-blueprint` 或 `seo-readiness-audit`，不急着要链接。

## 2. 拆竞品来源，不复制全部链接

从竞品引用域、排名页、用户常看的内容和相关社区中分类。treg 的 Backlinks / authority / domain metrics 已连接时，先用它取得目标竞品或目标页的 referring domains、链接页、锚文本与新失链线索；以实际返回字段为准，不假设接口名或把域级数字当排名结论。

```text
用户自发推荐
榜单 / 目录 / 测评
教程、内容收录或合作
PR / 创始人故事
社区 / 创作者传播
```

研究竞品为什么在那里出现，筛选自己相关、成本合理、符合规则且有机会获得的来源。团队资源、独家关系和长期品牌造成的链接是竞争背景，不是个人追赶清单。若 Backlinks 返回不可用、范围不完整或与页面实查矛盾，标缺口并回到公开页面/Chrome 验证，不用估算分数补结论。

## 3. 按三层判断每次引用

```text
用户可见、能点
→ 爬虫稳定可读
→ 相关且有编辑推荐价值
```

检查公开页面初始 HTML 是否有标准 `<a href>` 指向目标 URL；JS 点击跳转、社媒动态或资料页可能带来传播、访问和品牌发现，但不按稳定 SEO 权威估算。来源内容、锚文本与落地页任务一致时，深层链接比把所有链接堆首页更有价值。

## 4. 小范围分发并记录结果

先查社区规则、最近相关讨论和允许的参与方式。用平台原生语言展示问题、结果、样例或洞察；在有上下文的场合再说明产品。用户授权后才做对外发布、私聊、合作或付费收录。

为每个机会建立台账：

```text
来源 / 类型 / 规则或联系人：
竞品为何出现：
对应任务页：
预期：传播 / 发现 / 可能权威：
投入与日期：
实际：点击 / 任务完成 / 回应 / 引用：
下一步：
```

分享奖励只有在任务价值已成立、分享对象也能即时受益、单位经济可承受时测试；配归因、限额与防刷，而不是用虚假噱头刷传播。

**完成判据**：有一份只含可争取来源的机会台账；每次触达与具体任务页匹配，并记录真实行动而非只记录发了多少 URL。
