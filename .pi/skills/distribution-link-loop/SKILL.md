# distribution-link-loop

先让一张真实任务页完成用户结果，再研究它为什么值得被用户、作者或资源页发现和引用。

```text
已验证的用户任务与核心页 → 竞品/用户来源 → 具体推荐理由 → 小范围发现机会 → 完成与引用观察
```

## 1. 先确认要带去哪里

每次只选一个已经可用的核心任务页。写清：谁会在什么情境下使用、完成什么结果、为什么值得分享/引用、页面是否可抓取可索引。空壳页先回 `seo-site-blueprint` 或 `seo-readiness-audit`，不急着要链接。

## 2. 从竞品来源找可争取机会

需要反链、引用域、锚文本或竞品主力页时，先交 `treg-research` 并写清要改变的分发判断。抽样竞品来源后，不保留总数或分数解释，只问：

```text
这条来源把谁带到哪一页？
它为什么推荐这页？
我们的哪张已验证任务页能给同类读者一个更具体的结果？
```

将来源分成用户自发推荐、榜单/目录/测评、教程/内容收录或合作、PR/创始人故事、社区/创作者传播。只留下任务相关、符合规则、资源够得着且可能给真实用户带来发现的来源。团队关系、长期品牌和不可复制资源只作为竞争背景。

## 3. 判断引用是否值得争取

按顺序检查：来源用户能否看见并点击 → 页面是否有稳定可读的链接 → 推荐语境是否说明了我们这张任务页的结果。来源内容、链接文案和落地页任务一致时，优先争取深层任务页。

社媒动态和社区帖子首先用于用户发现与反馈；它们是否形成稳定搜索引用，要看真实页面结构和编辑语境。

## 4. 小范围分发并记录结果

先按目标人群出现的渠道找少量机会。需要社区原话或竞品内容时交 `treg-research`，再用 Chrome 核对上下文和规则。用问题、结果、样例或洞察解释这张任务页能解决什么；在规则允许且用户授权后才做发布、私聊、合作或付费收录。

为每个机会记录：

```text
来源与规则/联系人：
用户正在解决的任务：
为什么它会推荐这张页：
对应任务页：
实际：点击 / 任务完成 / 回应 / 引用：
下一步：
```

只有完成、回应或合资格用户行动发生时，才加码该来源。

**完成判据**：有一份只含可争取来源的机会台账；每次触达与具体任务页匹配，并记录真实行动而非只记录发了多少 URL。
