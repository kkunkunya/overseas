# treg-research

每次市场或竞品调研都从同一条链起步：外部信号只能帮助看见用户和现有供给；结论必须回到要交付的产品结果和需要验证的商业动作。

```text
同一任务的搜索/社区/竞品信号
→ 用户当前想完成什么、已经怎样凑合
→ 竞品入口、结果和下一步
→ 我们能交付的更窄结果
→ 用户会为哪个动作或单位付钱
→ 真实使用后才扩内容、引用和分发
```

## 1. 先写待决判断

每轮只处理一个会改变产品选择的问题，例如：

```text
同一任务下，用户是来立刻做事、理解结果还是购买服务？
竞品的免费结果之后，用户为什么会继续、保存或付钱？
现有内容/工具漏掉了哪一步，我们能否给出一个更窄、可履约的结果？
```

没有待决判断时，先回 `vertical-keyword-loop` 或 `direction-validator`。域名和关键词是取证对象；待决判断仍须是产品选择：这个付费站的逻辑能不能学、这些词能不能做成付费 App。

## 2. 按要消除的疑问选调用

| 要确认的事实 | 先查什么 | 结果必须回答什么 |
| --- | --- | --- |
| 用户是否主动寻找某个任务 | 任务词的 keyword ideas、volume、SERP；必要时 search intent | 用户是要立刻操作、理解、比较还是购买；我们应做什么首屏结果。 |
| 竞品怎样承接同一个任务 | 固定国家/语言/设备下的 SERP；page audit、domain/page ranked keywords；公开入口、结果、价格、sitemap | 用户从哪页进来，当场拿到什么，随后被带往哪里；这条链遗漏了什么。 |
| 竞品靠什么内容和页面继续服务用户 | 页面目录、相关内链、近期新增/排名页、公开样例和价格页 | 哪些内容是完成核心任务所需的说明，哪些只是长期内容库存；我们现在应做哪个，哪些留到真实需求出现后。 |
| 外部为什么提到竞品 | backlinks、linking domains、anchors；再打开来源页 | 链接落到哪张任务页，来源为何推荐它，是否有可争取的同类来源。 |
| 真人如何说问题和替代 | Reddit、TikTok、YouTube、Instagram、X 等少量相关帖子/评论 | 谁在什么时刻卡在哪一步，已经如何凑合，什么行动才可能发生。 |
| AI 回答会引用什么 | 目标问题的 AI response / mention，再核对传统搜索与来源页 | 当前来源提供了什么事实或工具；我们缺少哪一个真实资产。 |

先运行 `treg catalog search "<要确认的事实>"`，再运行 `treg catalog get <endpoint>` 看参数、成本与成功记录。输入不匹配、价格不合适或端点不可用时，换同一能力的端点，或转公开页面和 Chrome 核验；不猜接口，不把缺失数据补成结论。

## 3. 小样本调用并核验

- 每轮先定国家、语言、设备、对象数、预算和停止条件。市场竞品图默认从 3 个任务词、4–7 个实际前排独立站、每站 1 张核心任务页开始；正式样本优先选能沿公开链路走清「目标用户 → 可用结果 → 支付入口 → 成交或收入线索」的网站。只有流量、融资或功能展示的站点保留为需求或 SEO 样本，不能单独支撑生意判断；需要时才扩样。
- 使用 `treg call <endpoint> --method <GET|POST> --data '<JSON>'`。重试同一丢失结果时沿用 `Idempotency-Key`；新的观察使用新 key 或不用 key。
- 先对同一批主词取 SERP，再选正式样本。每站沿着 **入口 → 即时结果 → 样例/内容/账号 → 价格或回访** 走一遍；同一站的 App 商店页不能代替独立站链条。
- 对核心页抽样 page ranked keywords、page audit、backlinks 或 linking domains。来源样本必须打开复读，区分编辑推荐、用户传播、目录收录、同品牌语言页和无关背景。
- 关键用户原话、竞品承诺、价格、引用页和 AI 引用都要打开复读。返回数字、标签、排名或链接清单本身不构成产品结论。

## 4. 将竞品信号收成产品决定

报告只保留改变决定的事实。不要解释月搜、KD、CPC、SEO、GEO、SERP、反链等名词，也不要另列“固定研究维度”。

```text
竞品的用户入口 → 当场结果 → 下一步/付费或回访 → 产品基调
→ 我们学习什么 → 现在不做什么 → 需要哪一个用户行动验证
```

从多站归纳产品基调时，目的不是挑一个完整复刻，而是做取舍：

- 已被前排完整满足的基础工具或技术报告，不作为新产品的主承诺。
- 只在用户完成核心任务时才需要的说明、样例和限制，进入首版。
- 需要长期内容存量、真人供给、品牌或大量历史页面才成立的链条，记作竞争背景，不进入首版。
- 付费页只说明竞品怎样卖，不能证明用户会为我们的结果付费；用可履约 demo、保存/分享、询价或付款继续验证。

把不能从公开数据推得出的收入、转化、排名稳定性、外链权重和真实需求留为未知。

## 5. 路由

- 需要找付费参考站，或从成功站收核心词和长尾：回 `vertical-keyword-loop`。
- 需要判断人群、任务和产品路线：回 `direction-validator`。
- 词群和产品承诺已成立，需要页面树：交 `seo-site-blueprint`。
- 核心任务页已可用，需要争取用户、社区反馈或引用：交 `distribution-link-loop`。
- 已有明确 AI 问题，需要来源资产：交 `geo-source-loop`。

**完成判据**：本轮有可复核的外部事实，并明确改变了一个需求、产品、商业或分发判断；下一步是一个具体验证或页面，而不是继续导出数据。
