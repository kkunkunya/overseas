# 可引用内容、对比页与批量模板页

写三类页时读本文件：想让 AI 引擎不只引用、还推荐的页、竞品替代/对比页、批量模板页（pSEO）。各引擎的爬虫、开关、测量只在[规范手册](engine-playbook.md)；单页 brief、claim ledger、pSEO 的 go/watch/reject 门在[内容、多语言与 pSEO](content-scale-localization.md)。这里只补页面怎么写、怎么拆、怎么把关。

三类页共用一条底线：**先做一张页**，跑通任务、事实、引用三件事，再复制成一组。每条对外事实进 claim ledger；没核的写 `待核` 或删掉，不编数字、不编引语、不编"多少用户"。

## 一、写成 AI 愿意引用的正文

段落怎么写（每段对应一个问题、首句直接答、可引用句、证据与实体写法、Schema）只在 [GEO 写作规则](geo-writing-rules.md)，这里不重复。本节只补它没讲的一层：被引用之后，怎样才会被推荐。

**被引用不等于被推荐。** 页面有用，AI 会拿来当资料（引用）；但把你列进"推荐清单"主要看全网共识：评测、论坛、榜单、媒体。

| 层级 | 靠什么 | 归谁 |
|---|---|---|
| 被抓取 | 初始 HTML、爬虫放行 | 本 skill 完工体检 + 手册 |
| 被引用 | 段落可抽取、有证据、有日期 | [GEO 写作规则](geo-writing-rules.md) |
| 被点名 | 实体清楚：站名、做什么、给谁用在各处说法一致 | 本节 + `distribution-link-loop` |
| 被推荐 | 站外共识 | `distribution-link-loop` |

据此做两个判断：

- 新站别指望一篇自吹的 "best X" 榜单换来推荐。自己排第一的榜单常被拿去当品类资料，AI 引用了你整理的竞品名单，推荐的却是竞品。要写榜单，就先诚实写清品类领头者强在哪，再写本站在哪些场景更合适。
- 定位要处处一致（实体写法见 GEO 写作规则第 3 节）。About 页、首屏、各平台 profile 对"做什么、给谁用"说法统一；AI 描述错了或说得含糊，先在应该写明这件事的那一页上写明，再看站外。

```text
推荐层自查（每个核心页）：
自家榜单有没有先写清品类领头者强在哪？  首屏、About、各平台 profile 的「做什么、给谁用」是否同一句意？
AI 描述错时，站内哪一页本该写明这件事？
```

## 二、竞品替代页与对比页

**先选对手，不猜对手。** 任务或 SERP 里没出现具体竞品时先问，不围绕"大概是它"写完整页。候选按三条排序：用户真在搜（有 SERP/GSC/真实提问证据）、本站在某个场景确实更合适、对方事实可以核实。三条凑不齐就不做这张页。

| 页型 | 搜索意图 | 正文顺序 |
|---|---|---|
| `X alternative`（单数） | 想从 X 换走 | 为什么有人换 → 本站一句话定位 → 分项比较 → 谁该换、谁别换 → 迁移路径 → 换过来的人怎么说 → CTA |
| `X alternatives`（复数） | 还在调研 | 换的常见原因 → 挑选标准 → 4–7 个真实选项（含本站）→ 汇总表 → 逐个点评 → 按场景推荐 → CTA |
| `本站 vs X` | 直接比较 | TL;DR 2–3 句 → 对照表 → 按维度比（功能、价格、上手、支持）→ 本站适合谁 → X 适合谁 → 迁移 → CTA |
| `A vs B`（两家竞品） | 比较别人 | 两家概况 → 分维度比 → 各自适合谁 → 第三选项（本站）→ 三方表 → CTA |

每张页都要：开头 TL;DR；表格之外有段落解释差异在什么场景下重要；价格按档位比并算一个典型用法的总成本；"X 更适合谁"写真话。

**诚实规则（每条都假设对方团队会读）**：

- "没看到"不等于"没有"。对方价格页没列某功能，写"价格页未列出（截至 2026-10-10）"，或者删掉这行；只有文档或实际试用确认没有，才写 ✗。
- 竞品事实都标"截至"日期和来源 URL，表格上写明查阅日。
- 只写变了什么，不猜为什么变。
- 事实（对方站上写的）、解读（这对用户意味着什么）、建议（选谁）三层分开写。
- 不点名贬低，不用对方商标冒充合作，不引用无法回溯的评价。

**集中维护竞品数据。** 每个竞品一份数据（定位、价格各档、功能、强项、弱项、适合/不适合、常见抱怨、迁移要点、`last_verified`、来源），所有页面从这份取。改一次价格，全部页面同步；这份数据就是这组页面的 claim ledger。

**内链与维护**：建 `/alternatives`、`/compare` 两个 hub，列出全部页面，每项一句"更适合需要什么的人"，带更新日期；子页回链 hub，相关对比互链，功能页链到对应比较。按季度核价格和主要功能，用户或客服提到对方有变化时立即复核。复核时逐条标 `现行 / 已变 / 无法核实 / 过度声明`，无法核实的降级为"未列出（截至日期）"或删除，先改公开页。

## 三、批量模板页：在现有 pSEO 门上补什么

现有[程序化 SEO](content-scale-localization.md#程序化-seo)已规定 pattern 验证、样本、小批发布与退场。下面只补四件它没写细的事。

**1. 逐页唯一价值测试。** 任意两张同模板页互换变量名后，读者如果分不出来，后一张就不该单独存在。以塔罗站为例：78 张牌 × 正位/逆位 × 通用/爱情/事业 = 468 个组合。先看 SERP：如果 "tower reversed love" 和 "tower reversed" 返回的是同一批页面，就做一张逆位页、里面放爱情小节，不拆两张；只有 SERP 页型不同、内容确实不同的组合才单开 URL。组合数是上限，不是计划。

**2. 数据来源决定能走多远。** 按可防御性从强到弱排：自己创作的 > 产品使用产生的 > 用户贡献的 > 独家授权的 > 公开数据（谁都能抄，最弱）。每个字段写明来源、许可、更新方式和 owner。塔罗的牌义正文要有自己的解读和示例；公版资料（如 1910 年 Waite 原著）可以引用并注明出处，不能整段搬第三方站。来源许可不清楚的字段标 `待核`，不上线。

**3. 模板与变量的比例。** 模板只出骨架和导航，每页主体要来自数据驱动的条件段落：字段有值才显示，缺值时有 fallback 或整段隐藏，不输出空标题和占位符。抽样时数一数，去掉页头页脚和导航后，正文里有多少是这页独有的。独有部分撑不起页面任务的，归入 noindex 或合并，不靠 AI 改写同义句凑差异。平台先确认能做到四件事：服务端出 HTML、按字段条件分支、每页单独控制 `noindex`/canonical、sitemap 按页型拆分。

**4. 索引门：默认 noindex，过门才放。**

```text
新生成的页 → noindex，不进 sitemap（仍可抓取，用来验 HTML）
→ 抽样 QA：最强 20–50 页 + 数据最少、边界值、缺字段、疑似重复各若干
→ 通过：去 noindex，进按页型拆分的 sitemap，hub 链入
→ 不通过：修模板/补数据后重抽，或合并、保持 noindex
→ 已放行的页数据过期或被判重复：退回 noindex 并记入回滚清单
```

抽样每页核：任务能完成、事实对得上来源、没有占位符、title/H1 唯一、canonical 正确、没有和别的页抢同一个词（关键词互相蚕食）、有入链。

**hub/spoke 内链**：hub 是类目页（如"大阿尔卡纳"），spoke 是单牌页，同组 spoke 互链（相邻牌、同元素、对应的正逆位），每页都带面包屑并能从首页几次点击到达。不存在孤儿页；sitemap 只列已放行的页。
