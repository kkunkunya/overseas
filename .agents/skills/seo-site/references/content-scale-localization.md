# 内容 brief、维护、多语言与 pSEO

## 单页 brief 与内容维护

**触发**：需要新建/改进内容页，或查询、产品、法规、价格、链接、转化事实变化使旧页可能失真。

**输入**：页面任务、目标查询与国家/语言、站点事实、现有 URL/sitemap、SERP 页型、同一任务簇的用户问题、可引用来源、可复现的产品/服务示例、转化动作、上次更新时间、内容 writer 与事实 reviewer。

**步骤**：

**已有产品团队与职责**：已有团队带着明确页面、内容维护、多语言或 pSEO 交接时，可直接进入本 reference 的对应小节；历史立项材料缺失标 `unknown`，不重做需求立项。内容 writer 与事实 reviewer 是职责，`seo-site` 负责完成正文/事实台账，或安排含输入、交付物、来源、owner、未核验项和回交条件的交接。

1. 先将候选任务对照现有 URL，选择 `improve / merge / new / skip` 并写理由：已有页能承接时补缺失结果，重复任务考虑合并，独立任务且有可交付增量才新建，无相应价值则不做。改旧页保留仍有效部分，只列需加强/新增/删除的段落。候选都成立时优先处理与当前业务目标更近且有证据的缺口，不把成交近页设为所有站的必经顺序；未建站仍按首版任务合同规划。
2. 支持内容题目只从同一任务簇的真实用户问题，或已有实际工具授权的 GSC / AI 观察中提出；记录来源、日期、上下文和它补哪一步。它们不重开已锁定的核心 3+15，也不把未授权、未复读的数据写成事实。
3. 核对真实 SERP 与站内结构，过滤不属于同一任务的排名页；评分只能用于排序人工检查。
4. 写页面合同：用户任务、首屏答案/结果、独有信息、事实来源、H1/H2/H3、CTA、真实内链、索引角色和更新 owner。按页型补齐用户决策所需的适用/不适用条件、费用或限额、真实结果示例，以及下一步能得到什么；不要求每页都有价格或联系表单。
5. brief 通过后由内容 writer 继续写完可上线正文，不以提纲结束。正文须能独立完成页面任务，包含必要步骤、限制、CTA 和正常读者能理解的连接语。
6. 真实示例由 writer 在目标产品/服务中复现，或使用有出处的用户/业务材料；记录输入、环境、结果、截图/来源和复查时间。演示、合成或占位示例必须显式标示，不能冒充真实结果。
7. 建 claim ledger：逐项记录产品能力、价格、政策、统计、客户结果和引语的来源、状态、owner 与复查条件。事实 reviewer 核对高风险或易变 claim；未核实项改写为边界说明、移除或阻止发布。
8. 每个标题必须服务任务或回答真实问题；字数、关键词密度和固定词频只作过度/遗漏提示。
9. 发布后以查询、完成、转化、反馈和事实变化触发维护；没有变化时不为“新鲜度”做空改。

**判断**：站点无法兑现的主题删掉；没有独有结果/事实的页合并；外部事实过期或来源失效时先降级声明或暂停发布。

**输出**：brief、可上线正文、真实/演示示例清单、claim ledger、支持题目的任务簇来源，以及给工程的 keep/add/remove、内链和更新检查。

**验证与交棒**：逐条回指产品事实、来源和真实 URL；在 staging 对照正文检查无占位符、示例标示准确、链接/CTA 可用且页面能完成任务。工程负责装页和交互实现，发布前回 `seo-site` 做完工体检，效果交 `product-growth-review`。

## 多语言/多地区

**触发**：首阶段明确要规划多语言/多地区，或团队准备服务另一市场。准备态现在即可确定 locale、URL、owner 和示例，不要求第二市场已有流量；执行上线仍需当地任务与可交付性核对、内容及技术审核，不因“全球化”自动复制全站。

**输入**：分别列国家/地区和语言、页面任务、当地用词、产品/价格/支付/支持、源页与 URL 策略、内容/工程/本地审核 owner。准备态缺失的市场证据、承诺和 owner 标 `待核`；大企业案例记录具体 URL、观察日期、事实/推断/未测，不能把其资源或商业能力套到本站。

**步骤**：

1. 先拆“服务哪里”和“用什么语言”：一个国家可有多种语言，同一语言可服务多个国家。为一个核心任务列候选 locale、URL、交付差异和 owner；尚未进入的市场保留准备态，不以缺流量退回选词。
2. 优先用 Apple 等大企业的第一方页面做对照案例：从国家/地区选择页找到**同一任务**的多 locale URL，比较主文案、价格/币种、可买商品、支付与支持承诺、切换入口及切换后是否保留任务。区分页面可见事实与实际交易/支持结果；路径相似不证明内容等价，企业规模不证明做法最佳。
3. 将观察转为本站的小样本方案：翻译意义、真实例子、货币/日期和当地承诺，品牌/产品事实保持一致；先写可审示例及差异表。未核实的例子标 `模拟`，产品/支付/支持未知记待核，不能发布无法兑现的承诺。发布前逐市场核对任务、SERP 页型和商业可交付性，本地 reviewer 审关键语义；自动翻译只作草稿。
4. 按下列 Google 规则建立 locale URL 矩阵；企业页面是实现观察，Google 文档是搜索规则来源，不能从 Apple 的可见页面猜 canonical 或 hreflang。技术观察须记录取证方式、响应/HTML/注解载体；未检查的载体记 `未测`。
5. 每个版本使用可独立访问的 URL，提供可发现的地区/语言切换链接，避免依赖 IP 或猜测语言强跳。核对切换后的任务、正文、CTA、付款与支持，不只检查导航被翻译。
6. 发布前按矩阵验等价内容、canonical 决策、hreflang、自引用/回链、状态和可索引性；只将已审核且真实存在的版本加入注解。保存 QA 与回滚，发布后再按 locale 观察抓取、查询和任务完成，不能以案例或静态检查证明排名效果。

**Google 规则核对（查阅日 2026-09-06，实施日再复核）**：

- 对真正不同语言、需独立索引的版本，通常使用自指 canonical；同语言地区的相似/重复页按 Google 规则评估首选 canonical，并配合 hreflang，不能统一将所有语言 canonical 到英文。
- hreflang 只关联同一任务的等价内容版本，包含自引用和对应版本回链，使用完整 URL 与有效语言/可选地区 code，如 `en-US`、`en-CA`、`fr-CA`、`zh-TW`；地区不能单独充当语言。选择 HTML、HTTP header 或 sitemap 中适合的载体，不要求重复实现全部载体。
- `x-default` 按未匹配语言用户的实际 fallback/选择页需求设置，不是每页强制项，也不等于所有页面的 canonical。
- 正确设置 `html lang` 有其语义用途，但 Google 根据可见内容判断语言，不以 `html lang` 或 hreflang 代替语言识别；只翻译导航不足以构成完整语言版本。

规则来源：[Google 多地区与多语言站点](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)、[Google 本地化版本与 hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions)。

**准备态示例（模拟，非已上线 URL）**：同一任务拟用 `https://example.com/us/task/`（美国/英语，`en-US`）、`https://example.com/ca/task/`（加拿大/英语，`en-CA`）、`https://example.com/ca/fr/task/`（加拿大/法语，`fr-CA`）。内容 owner 写任务与差异，本地 reviewer 核对价格/支持，工程 owner 实现路由与注解；具体人选待确认。英语两地区的 canonical 待内容近重复评估；法语在完整翻译且需要独立索引时通常自指。未发布 URL 只留在规划矩阵，不写入线上 hreflang。

**判断**：缺第二市场流量不阻塞规划；只有翻译资源、无当地交付/需求证据时将上线标 `watch`，保留已完成规划。内容不等价时不强绑 hreflang，缺本地审核或当地不可交付时不发布。不声称 Apple 一定最佳或复制即可排名。

**输出**：准备态交国家/语言/locale/URL/owner 矩阵、案例事实与适用性、首批页示例、待核清单、canonical/hreflang 决策和审核合同；执行态再交审核通过的正文、技术注解、QA、回滚与发布证据。

**验证与交棒**：准备态 walkthrough 覆盖“无第二市场流量”“同语言地区近重复”“不同语言等价页”，能说清当前产物和上线缺口即可交回。执行态抽查源页和每个 locale 的初始 HTML/注解载体、canonical/hreflang/内链/语言/关键交易路径；工程交产品仓，搜索就绪回 `seo-site` 完工体检，发布效果交 `product-growth-review`。

### Apple 短案例（官网页面观察，2026-09-06）

[国家/地区选择页](https://www.apple.com/choose-country-region/)同时列出 Canada (English)、Canada (Français)、United States 与台灣入口。独立研究者保存的当日初始 HTML 字段摘录覆盖同一 iPhone 17 产品的四个版本，可作为国家与语言分开建模的样本：

| 国家/地区与语言 | 当日页面 | 少量已核 HTML 事实 |
| --- | --- | --- |
| 美国，英语 | [US iPhone 17](https://www.apple.com/iphone-17/) | `lang=en-US`，description 使用 colors |
| 台湾，繁体中文 | [TW iPhone 17](https://www.apple.com/tw/iphone-17/) | `lang=zh-TW`，繁体中文 description |
| 加拿大，英语 | [CA English iPhone 17](https://www.apple.com/ca/iphone-17/) | `lang=en-CA`，description 使用 colours |
| 加拿大，法语 | [CA Français iPhone 17](https://www.apple.com/ca/fr/iphone-17/) | `lang=fr-CA`，法语 description |

四页摘录均为自指 canonical，hreflang 包含自身与另外三个样本；该次产品页 HTML 提取中未见 x-default。这只记录四页的实现，不能替本站决定同语言近重复页的 canonical。页脚均链接地区选择页，选择页再到地区首页；这不是同产品一键切换的证据。

可借鉴的是“同一任务的 locale URL + 当地内容核对 + 用户选择入口”，不是复制 Apple 的目录名、规模、价格或服务能力。价格/支付/支持承诺应按上方步骤另查；本小样本未逐项验证价格、实际付款、支持履约或浏览器切换行为，也无 Google 实际 canonical/索引/排名数据。未查的 HTTP header、sitemap 或其他页面保持未测，不推断全站注解或效果。

## 程序化 SEO

**触发**：已有重复搜索模式、可靠数据和单页价值，人工样本能证明模板不只是换变量。

**输入**：查询 pattern、实体/变量、数据来源与更新频率、模板、唯一价值规则、索引/内链策略、质量与回滚 owner。

**步骤**：

1. 证明 pattern 与 SERP 意图；列可生成组合，但不把组合数当机会。
2. 对每页定义独有数据、计算、比较、库存或工作流结果；只有公共字段替换的页不进入索引集。
3. 先做少量代表样本，覆盖高/低数据量、边界值、缺失值和重复意图。
4. 对样本检查真实任务、事实准确、模板 fallback、canonical、重复/孤儿、内链、sitemap、Schema 与渲染。
5. 小批发布并观察抓取、索引、查询、任务完成和转化；只有样本与首批通过才扩大。
6. 数据过期、模板错误或页面无独有价值时，停止新增，修复、合并或 noindex；保留可回滚清单。

**判断**：数据不可维护、页面不可区分、搜索任务不存在或产品无承接时 `reject`；信号存在但质量 owner 不足时 `watch`；通过样本才 `go`。

**输出**：pattern/data contract、样本集、模板与 fallback、索引/内链计划、批次 gate、监控与退场规则。

**验证与交棒**：人工复核代表样本并用抓取结果核对初始 HTML；工程实现后回 `seo-site` 完工体检，窗口结果交 `product-growth-review`。

逐页唯一价值测试、数据来源等级、模板与变量比例、默认 noindex 的索引门、hub/spoke 内链见[可引用内容、对比页与批量模板页](citable-comparison-template-pages.md#三批量模板页在现有-pseo-门上补什么)。
