# seo-site

一份骨架走两遍：**开工**时把已取证的客户任务变成页面清单和每页说明书，**完工**时拿同一份清单逐页体检，外加上线前把数据点埋好。两遍用同一张页面清单和同一张 E-E-A-T 体检表，前后不会对不上。

```text
客户任务 + 锁定的 3+15 → 页面清单与 brief（含信任页）+ 体检表「改前」→ 可上线正文 → 产品仓实现
→ 完工体检（搜索引擎 + AI 引擎 + 体检表「现在」）→ 埋点验证 → 上线 → 中文讲解页
```

## 每次先做：核对引擎规范

搜索和 AI 引擎的规则变得很快。每次用本 skill，先读[搜索与 AI 引擎规范手册](references/engine-playbook.md)，按其中「怎么更新」一节主动查一遍各家官方来源有没有新变化：新爬虫、新开关、新报告、新的推荐或不推荐做法。发现变化就当场用上，并按手册写回（查阅日、来源、影响），不等别人提醒。实际项目里踩到的坑、验证过的做法，也写回手册的「实战经验」。

## 根：E-E-A-T

被抓到只是进了候选池；Google 排序和 AI 引擎挑引用来源，都在候选里找最可信、最直接回答问题的那页。所以本 skill 的每条规则都挂在 E-E-A-T 下，Trust 在中心，Authority 只能在站外挣。读[E-E-A-T 框架](references/eeat-framework.md)：四维定义与常见误读、Who / How / Why 自查（含 AI 生成的披露）、YMYL 边界、站点层信任页清单、Authority 交接，以及各份规则分别补哪一维。E-E-A-T 不是一个分数，只能把信号一项项做实。

## 一、开工：画骨架

已有页面要判断内链/外链、选工具、做 AI 单页审计或控制内容扩量时，读[出海 SEO 执行清单](references/overseas-seo-checklist.md)，只选当前缺口对应的一组，交最多三项改动及复查方式；其五条收藏是经验来源，不替代引擎规范。

要画新站首版，需要锁定的词和客户任务证据；不足时先报告缺什么，不为补词重开选词。已有站做补页、维护、多语言或 pSEO 时，历史材料缺失记 `unknown`，当前任务和真实 SERP/用户信号够就继续。

**按任务拆站，不按字面词堆页。** 对每个候选页回答：用户带着什么任务进来？首屏怎么承诺？在这页完成什么结果？为什么父页或别的页替代不了？同一任务的近义词、拼写变体合在一页；目标、流程、结果或 SERP 页型不同才拆。

**画主题树与页面角色。** 用 `核心任务页 → 子任务页 → 场景/问题页` 组织，标父子内链和相关内链。每个 URL 标一个角色：

| 页面角色 | 搜索处理 |
|---|---|
| 要拿搜索和 AI 流量的工具、内容、比较、目录页 | 可抓取、可索引、列 sitemap、从浅层内链抵达 |
| 公开但不参与排名的登录、筛选、重复或过渡页 | 允许抓取以读取 `noindex`，不列 sitemap |
| 用户数据、账单、后台 | 权限控制；robots 只减少无价值抓取，不当安全边界 |

**画信任层。** 按[E-E-A-T 框架](references/eeat-framework.md)第 4 节把 About、方法说明、法务与退款、收款方说明、官方支付标志、署名（适用时）放进页面清单；法律主体没成立只写真实的。复制[E-E-A-T 体检表](assets/eeat-scorecard.md)进项目文档打「改前」分，0 分项变成页面清单或 brief 里的条目。

**每页写 brief：**

```text
页面/规范 URL：
用户任务与词群：
页型与首屏承诺：
核心输入 → 结果（或答案）：
Title / 单一 H1：
H2/H3 子问题：用途、场景、步骤、优势、限制、FAQ：
主要 CTA：
父页 / 子页 / 相关内链：
索引角色：
可被引用的事实：样例、数据、比较、限制、工作流（AI 引擎引用的正是这些）：
信任信号：这页补 E-E-A-T 哪一维、Who / How / Why 在哪里看得到、YMYL 边界声明：
问题表：每块（H2 / FAQ 条）对应的搜索问题、首句答案、可引用句、事实来源、结构化数据类型：
首版必须做 / 真实使用后再做：
```

功能先让用户完成任务，文字让搜索引擎、AI 引擎和首次访问者理解任务、用法和边界。字数、关键词密度只作复核提示。

**交出可上线正文，不停在提纲。** 本 skill 负责正文、真实示例和事实台账（claim ledger），或安排具名的内容 writer 与事实 reviewer，写清输入、来源、交付物、未核验项和回交条件。写正文、FAQ 和结构化数据前读[GEO 写作规则](references/geo-writing-rules.md)：每段对应一个搜索问题、首句直接答、每块至少一句可引用的话、实体与事实全站一个写法、Schema 只标可见内容。文字底线归 `anti-slop-frontend` 的 copy-gate：强档撰写定稿，`scan-ai-tone.py` 过一遍，没有凑字数段落。未核实的 claim 待核或删去。单页写作/维护、多语言、pSEO 到条件时读[内容、多语言与 pSEO](references/content-scale-localization.md)；首阶段就要多语言规划时可直接进入其准备态。写竞品替代/对比页（`X alternative`、`A vs B`）、批量模板页，或想让 AI 不只引用、还点名推荐时，读[可引用内容、对比页与批量模板页](references/citable-comparison-template-pages.md)。

**首版范围：** 一个兑现主承诺的核心页、支撑理解和信任的必要内容、最少的相邻任务页及其内链。登录、复杂套餐、后台、大规模 pSEO、未验证语言版本放进「稍后验证」。

## 二、上线前：埋点

上线后要分析数据，前提是上线前埋对了。从要做的业务决定倒推：

```text
访问 → 开始用 → 完成任务 → 注册 → 付款 → 回访/分享
```

每个事件写触发点、必需属性、来源（含 UTM 与 AI 引擎来源，见手册「测量」）、去重、测试数据排除、owner。用一条成功路径和一条失败路径走一遍「前端 → 采集 → 报表」，核对顺序、身份、金额。线索型业务先定义什么算有效询盘。

没走通的事件标 `unknown`，不当基线用。无数据不等于零。埋点实现交产品仓；验证过的基线交 `product-growth-review`，上线当天从它开始算。

## 三、完工：体检

拿开工那份页面清单逐页过，按最早阻塞排序。输入缺页面任务或 URL 角色时先报告。

1. **页面完成任务吗**：首屏或早段直接给结果、答案或开始路径；正文每块能在问题表里找到对应的搜索问题和可引用句，找不到的块标为删除候选；事实、价格、统计能回到一手来源；H1–H3 按任务推进；图有 alt、标来源；Schema 只标页面上真实可见的内容。要改页面任务或正文时回到第一段改 brief，不在体检里硬补。
2. **服务器返回的初始 HTML**：主体直接含核心任务、承诺、说明和链接。关键内容只在客户端 JS 跑完才出现时标阻塞，改 SSR/SSG/预渲染——大多数 AI 爬虫不跑 JS，这一条对 AI 引擎更要命。同时查状态码、唯一 canonical、title/description/单一 H1、无意外登录墙或循环跳转。
3. **抓取、索引、sitemap**：robots.txt 管抓不抓，`noindex` 管收不收。想让公开页不出现在结果里，就放行抓取让它读到 `noindex`。sitemap 只列要排名的规范 URL；每个索引页至少一条语义内链。
4. **各引擎逐家过一遍**：按手册的「逐家清单」核对 Google、Bing、ChatGPT、Perplexity、Gemini、Claude 等：各家搜索爬虫是否放行、训练爬虫的取舍是否是人拍板过的、各家的所有权验证与提交入口（GSC、Bing Webmaster、IndexNow 等）、各家 AI 引用开关的决定。每家标 `可用 / 待接入 / 不适用`。
5. **E-E-A-T 复评**：同一张体检表打「现在」分，只按当天线上可见的打；Authority 行取 `distribution-link-loop` 的观察，没有就写 `?`。Trust 缺口排在其他维度前面。
6. **上线交接**：涉及支付、域名、部署、迁移、性能、Schema 时读[上线、测量与技术迁移交接](references/launch-technical-handoff.md)，并按[网站上线与持续检查](../ask-selfmedia/references/website-operations-loop.md)记录；只执行已授权层级，准备完成不冒充真实上线。

输出：

```text
阻塞上线：
影响用户任务、信任或理解：
影响搜索引擎收录/理解：
影响 AI 引擎抓取/引用：
埋点状态：
E-E-A-T 体检表（改前 / 现在 / 下一步）：
可后置观察：
每项证据、责任位置与复查方式：
```

**每轮站内 SEO / GEO 改动都出一份中文讲解页**，按[讲解页模板](assets/seo-geo-briefing-template.html)：本轮在做什么、E-E-A-T 速览、四层架构前后对比（页面 / 内容 / 机器可读 / 规则）、体检表、文案改前改后、资源清单、参考的 skill、证据边界与下一步。资源与参考 skill 从[资源库](references/source-library.md)挑本轮用到的行；新来源先按其刷新规则写进资源库。讲解页作为附件发到任务评论，是人持续了解这块的固定渠道。

上线后没排名，先按「页面完成任务 → 可访问 → 抓到 → 收录 → 匹配意图/页型」查，再谈竞争和外链；观察窗未满不退回选词、不归档。

## SEO / GEO

本 skill 是出海 SEO / GEO 的总纲，各份规则都挂在 E-E-A-T 下：

| 规则 | 管什么 | 主要补的维度 |
|---|---|---|
| [E-E-A-T 框架](references/eeat-framework.md) + [体检表](assets/eeat-scorecard.md) | 根：四维、信任页、YMYL、开工与完工评分 | 全部，Trust 优先 |
| [GEO 写作规则](references/geo-writing-rules.md) | 每段回答哪个问题、可引用句、实体与事实单源、Schema | Expertise、Experience、Trust |
| [引擎规范手册](references/engine-playbook.md) | 各家爬虫、开关、测量 | 前提：抓得到 |
| [内容、多语言与 pSEO](references/content-scale-localization.md)、[上线交接](references/launch-technical-handoff.md) | 规模化、多语言、迁移 | Trust（不做规模化滥用、不丢页） |
| [资源库](references/source-library.md) + [讲解页模板](assets/seo-geo-briefing-template.html) | 规则出处与刷新；每轮给人讲清改了什么 | — |

站外 Authority（外链、目录、社区、AI 引擎实际引用、`sameAs` 时机）归 `distribution-link-loop`，交接写在框架第 7 节。其他出海 skill 的「SEO / GEO」一节写的是它补哪一维、交什么给这里。

## 边界

只做判断、合同和交接，不写产品代码；代码、部署进独立产品仓用 `/implement`。上线后的分发与 AI 推荐来源交 `distribution-link-loop`，数据复盘交 `product-growth-review`。整张地图见[出海全图](../ask-selfmedia/references/lifecycle-route.md)。
