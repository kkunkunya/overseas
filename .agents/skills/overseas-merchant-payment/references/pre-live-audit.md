# 支付链路体检清单

切真钱之前逐条读代码核对。每一条都写了：出事时是什么样、去哪查、怎样算过。只读，不改代码；没过的开成任务。

## 必须修

### 1. webhook 核对「哪家店、哪个模式」

- **失败表现**：MoR 平台一般用全平台共用的公钥验签，验签通过只能证明「这条通知是平台发的」，不能证明「是我们店的单」。别人注册一个免费测试店，把通知地址填成我们的站，用测试卡下单，就能给自己的账号加点数或开通会员。
- **去哪查**：webhook handler 里，验签之后、发放权益之前。
- **怎样算过**：payload 里的店铺 ID 等于我们的店铺 ID，模式等于当前环境（正式站只接受 live），两项都不等就丢弃并返回 200。

### 2. 测试和正式分开

- **失败表现**：测试店的通知打到正式站，测试订单写进正式库；切 live 后测试账号还带着会员身份。
- **去哪查**：平台后台的 webhook 地址、各部署环境的环境变量、数据库里测试订单的来源。
- **怎样算过**：测试通知只打到预览或测试环境；正式环境只有 live 密钥和 live 商品 ID；测试数据已清掉或做了标记。

### 3. 站内能取消订阅

- **失败表现**：「管理 / 取消订阅」入口依赖一个没配的环境变量，用户找不到取消的地方。美国对订阅「能方便取消」查得很严。
- **去哪查**：账户页、定价页的会员视图、平台的客户自助页地址。
- **怎样算过**：已订阅的用户在账户页始终能看到入口，点进去能取消、申请退款。

### 4. 审核要看的页面

见 SKILL.md 第 3 段。以正式域名上实际打开的结果为准。

## 应该修

### 5. 退款时连会员身份一起收回

- **失败表现**：退款后只扣回了点数，页面还显示会员，还能买只有会员才能买的商品。
- **怎样算过**：退款或拒付事件同时撤销会员身份和没用完的权益。

### 6. 重复通知返回 200

- **失败表现**：幂等拦截把重复通知当成错误，返回 401 或 409。平台后台一直显示投递失败，还会继续重发。
- **怎样算过**：已经处理过的事件返回 200，并且不重复发放权益。

### 7. 补发和对账工具

- **失败表现**：平台的重试次数有限（查文档），几次都失败的话，用户付了钱却拿不到东西，也没有工具补发。
- **怎样算过**：能按订单号从平台拉回订单并幂等补发；有办法列出「平台有、我们库里没有」的订单。

### 8. 升档、降档、月付年付互换

- **失败表现**：已经是会员的用户想换档位，被「已是会员」挡住，而平台自助页又不支持换档。
- **怎样算过**：至少低档升高档能走通，只扣一次钱，权益正确。其余情况写明怎么处理，或者明确说暂不支持。

### 9. 付款后的回站状态

- **失败表现**：用户付完回到站上，权益还没到账时显示「付款失败」；新商品回站后的提示认错类型（开通了会员，却显示「点数已到账」）。
- **怎样算过**：付款成功但还没到账时显示「处理中」并自动刷新；每个在售商品都有对应的提示文案。

### 10. 价格单一来源

- **失败表现**：代码、定价页、平台商品、审核表里的产品介绍，四处价格对不上。
- **怎样算过**：价目表只有一个来源；平台上在售的商品和它一一对应；年付价格等决策在上真钱前定下来，上线后再改价会牵涉老用户。
