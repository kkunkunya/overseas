# 出海收款：从沙箱到真钱

这件事有五段，顺序不能换：**选平台 → 代码体检 → 审核材料 → 代填并提交 → 审核后切 live**。每段都有一个会让人白等一周的坑，下面把它们放在各段里。

平台的费率、额度、审核时长、限制行业名单都是会变的状态，本 skill 不存具体数值。每次在执行当天查官方文档，回复里写上来源链接和查询日期。

## 0. 先读个人档案，不要重复问人

商户审核要填的姓名拼音、主体类型、税务居住地、自我介绍、公开链接，都存在自媒体项目仓库（`kkunkunya/new-self-media`）的 `brand/个人档案.md`。用 `multica repo checkout` 或项目资源定位它，只读。

- 档案里有的直接用；缺的才问，问完提醒人补进档案（写档案另开自媒体任务，不在本次运行里跨目录写）。
- 身份证号、银行卡号、验证码、密钥不进任何文件、评论或回复。它们只能由本人在平台页面里输入。
- 「为什么做这个站」这类主观理由要用人的原话。档案里没有就问一句；实在要代写，交付时明说是代写的。

## 1. 选收款平台：按当下条件比，不预设答案

Waffo、Stripe、Creem、Paddle、Lemon Squeezy、Polar 等都是候选，没有默认赢家。上一个站选了谁不是理由，这次要按这次的主体、品类和商品重新比一遍。

**先把候选分两类**，因为分类决定了税务和争议由谁扛：

- **MoR**（Merchant of Record，平台当法律上的卖家，代收销售税 / VAT，自己处理争议）：如 Waffo、Creem、Paddle、Lemon Squeezy、Polar。
- **PSP**（只做收单，卖家是你自己，税务和争议自己处理，费率通常更低）：如 Stripe。

某个平台属于哪类、支不支持某项，都以当天官方文档为准，不凭印象。

**再逐个候选查这几项**，每一项都要有官方链接：

| 维度 | 要查什么 | 为什么会一票否决 |
|---|---|---|
| 谁能开户 | 支不支持以大陆个人身份开户；要不要护照、海外公司、海外手机号 | 开不了户就不用往下比 |
| 品类 | 禁售 / 受限行业页逐条对（玄学、算命、约会、成人、金融建议、AI 生成内容常在名单上） | 在受限名单上，即使开了户也有冻结风险，只能算备选 |
| 提现 | 能不能结算到人手上已有的账户（国内银行卡、支付宝、PayPal、海外卡），币种和提现门槛 | 钱出不来等于没开 |
| 抽成 | 费率 + 每笔固定费，对**最便宜那档商品**算一次实际抽成比例 | 固定费对小额加购包影响很大，比例过高要提醒人重新定小包价格 |
| 订阅能力 | 升档 / 降档 / 按比例折算、客户自助取消与退款、试用、优惠码 | 站上要卖多档会员时，平台不支持换档就得自己绕，工作量大 |
| 接入成本 | 有无官方 SDK、webhook 签名、沙箱；本机有没有现成 CLI 或脚本（见 `/local-tools`：目前有 `stripe` 和 `waffo.mjs`）；项目已经在哪个平台的沙箱上跑通 | 换平台要重写 checkout 和 webhook，这是真实成本，但不是不换的理由 |
| 审核 | 审核要看什么、被拒后多久能重交 | 决定第 3、4 段要准备到什么程度 |

**输出**：把候选排成一张表（行是平台，列是上面各维度，格里写结论 + 链接 + 查询日期），被一票否决的标出原因。给出推荐和理由，再列出「什么条件变了会换选择」，比如人办了护照、注册了海外公司、品类被某平台放行。

**由人拍板。** Agent 只推荐，不替人定。定下来后写进项目的决策记录（ADR 或项目文档），后面几段按选定的平台走。选定的平台在 `/local-tools` 里没有现成工具时，按它的官方文档操作，不要套用别家的流程。

## 2. 切真钱前的支付链路体检

读代码，逐条对照 [支付链路体检清单](references/pre-live-audit.md)。清单列出了每一项的失败表现和查法。只读，不改代码；发现的问题按下面的分法开任务：

- **必须修**（不修不能切真钱）：webhook 没有核对「是我们的店 + 是正式模式」、测试和正式没分开、用户在站内取消不了订阅、审核要看的页面缺失。
- **应该修**（不挡上线，但迟早出事故）：退款没有收回会员身份、没有补发工具、重复通知返回了 4xx、升档或降档没有路径、付款后的提示文案认错商品。

正在生效的安全漏洞（比如能刷点数）单独开一张任务，排在最前面。

## 3. 审核材料：每一页都在正式站上打开过才算有

审核员会点表单里填的链接。常见的必备项：

- 服务条款（Terms）、退款或取消政策、隐私政策
- 页面上能看到的客服邮箱，并且确认这个邮箱真的能收信
- 品类要求的免责声明（比如「AI 生成，仅供娱乐和自我反思，不提供医疗、法律或理财建议」）
- 页脚每页都有以上链接
- 定价页的价格和平台上建的商品一致

**判断标准是「正式域名上打开返回 200，内容写对了」，不是「任务已关」或「代码已合进 dev」。** 页面代码合进了开发分支、还没部署到正式站，打开就是 404，审核员看到就会拒。逐个 URL 实际请求一次，把结果列成表。

同时核对商户店铺里在售的商品：和这个站无关的商品先下架（需要人同意），否则审核员会觉得店铺和网站对不上。

## 4. 代填后台审核表

浏览器操作走 `/browser`。人自己登录，登录链接原样交给人，不藏进子任务。

**Agent 可以代填**：店名、商家名称 / 账单描述、网站和政策页 URL、产品介绍（功能、所有价格档位、交付方式、取消方式、目标用户）、合规确认勾选、从档案读到的身份字段。

**必须本人填**：证件号、银行卡、收款账户、手机或邮箱验证码、任何需要签名或人脸的步骤。停在那一页，告诉人菜单路径。

填表时的规矩：

- **姓名按证件和银行卡户名的格式填**（如 `SHI XIAOKUN`：大写、姓在前、中间有空格）。户名不一致会导致打不了款。拿不准格式就问人。
- **先看页面再承诺。** 在后台找到对应设置之前，不要对人说「我去改 X」。有的设置根本不存在，有的在别的步骤里（比如账单商户名可能就在审核表里）。找不到就如实说。
- **平台必须发的邮件关不掉**（比如 MoR 作为卖家必须发的收据）。这时要改的是我们自己的产品，不要再重复发一份。续费前的提醒按目标市场的自动续费规定保留。
- 每填完一步，读回页面上的字段做核对。翻到下一步再退回来，确认内容还在。
- **「提交」前停下，等人明确回复「提交」。** 被拒后通常要等一段时间才能重交（以平台文档为准）。提交前先跑一次平台自带的网站自检（如果有）。
- 提交后**刷新页面**，确认状态变成审核中，截图作为回执。没刷新的标签页会一直显示提交前的样子，人会以为没交上。

## 5. 审核通过后切 live

| 谁 | 做什么 |
|---|---|
| 本人 | 绑定收款账户（户名和审核表上的姓名一致），输入验证码 |
| Agent | 在正式模式建商品（和测试模式的 catalog 一致），配正式 webhook，把正式环境的密钥和商品 ID 换成 live 值后重新部署。平台资源操作走 `/local-tools` 里的工具，没有就按官方文档 |
| 本人 + Agent | 用真卡买最便宜的一档，确认到账、会员或点数发放正确；再退款，确认会员和点数都收回了 |

任何 live 写操作、退款、上架（publish）都要先把对象 ID 和影响摆给人看，等人回复确认再做。

## 回执

每段结束时回复这几项：做了什么、哪些是本人要做的（给出菜单路径）、证据（URL 状态表、截图、平台文档链接和查询日期）、下一步卡在谁身上。代码问题开成 Multica 任务，交给当前 agent，并加载自媒体方向的相关 Skill。
