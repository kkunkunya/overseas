# product-definition

选品回答「值不值得做」，这里回答「做成什么样」：**产品形态的本质是帮用户解决麻烦**，每个模块都要对得上主推点和用户心理，也都要算清留存和付费。通用原理，不绑品类，C 端 B 端都按这一套走。

```text
选定的方向 → 主推点和用户 → 核心路径 + 5 秒 Aha 屏 → 模块账 → 收费设计 → 验证机制 → 产品定义（+ 讲给 Kun）
```

## 先决条件

要有一个已过 `direction-validator` 的方向（至少有哪种钱、五问答案、五特质判断）。没有就先回去选，不在这里补方向判断；Kun 直接点名一个方向时，按他的原话先写出这几项，缺的标 `待验证`，不编。

若选定形态是主题工具站簇，沿用选品交来的[工具站路线](../direction-validator/references/tool-site-loop.md)与逐站假设台账：本轮只定义 1–2 个输入→结果完整的小工具、共用模板和必要差异；把复查日期、指标口径、投入上限交给 `product-growth-review`，不另改通过/放弃阈值。保存、监控、协作、账户和收费扩展由真实后续行为证明后再加。

## 做法

五个特质在选品时用来判「值不值得」，这里改用来设计「怎么做」。原理不重写，读[选品那一页](../direction-validator/references/money-and-traits.md)，对应关系：

| 特质 | 到这里变成的设计问题 |
|---|---|
| 用户心理 | 主推点一句话，对准选品写下的**用户买的心理结果**（不是功能）；每个模块顺着还是逆着这个心理 |
| 特殊性 | 哪一屏、哪一步让用户觉得「这是为我的情况做的」 |
| 5 秒 Aha | 核心路径里哪一屏第一次看到结果；它必须最靠前 |
| 持续帮助 | 订阅还是单次，回访钩子放在哪 |
| 商业价值 | 付费墙放在用户最想拿到那个心理结果的一刻，每个模块的账 |

1. **主推点和用户**：哪群人、什么时刻、带着什么情绪、要摆脱什么麻烦，压成一句主推点。主推点、Aha 屏的画面、付费墙文案都要对准选品写下的心理结果；选品没写就先按用户原话补，标 `待验证`。写不成一句就还没想清，不往下走。
2. **核心路径**：从进来到拿到结果最短的一条，画成图。**先定框架和关键屏，再加功能**：先问「这个产品给谁用、要什么样的 UI/UX」，把屏的骨架立住，再往里填功能。5 秒 Aha 落在哪一屏要写明，那一屏用户看到的画面写出来。
3. **模块账**：列出所有想做的模块，每个填三栏——**省了用户什么麻烦 / 对留存的作用 / 对付费的作用**。三栏说不清的模块砍掉或推后到「以后」栏。账怎么填见[模块账与收费](references/module-ledger.md)。
4. **收费设计**：付费墙放哪个结果节点、订阅还是单次、漏斗怎么走、扣成本后的利润口径。同上一页。
5. **验证机制**：上线前后用什么方法验证「用户心理是真的」。同上一页。
6. **成稿并讲给 Kun**：按[产品定义模板](references/definition-template.md)写，**主动用人话讲一遍**，附核心路径图（Mermaid），不等他问；讲法是主推点、路径、砍了什么、钱在哪个节点收。

## 边界

产品定义交给下游，不重复它们的活：

| 事 | 归谁 |
|---|---|
| 这个方向值不值得做、哪种钱、五层筛 | `direction-validator` |
| 屏与屏之间的跳转图、按钮去向、UX 链留档 | `interaction-graph`（本 skill 只给核心路径和关键屏，不画全站跳转） |
| 页面清单、页面 brief、信任页、搜索引擎与 AI 引擎体检 | `seo-site` |
| 把选定的屏实现成界面并验收 | `anti-slop-frontend` / `/implement` |
| 上线后的数据复盘、转化与定价实验 | `product-growth-review`（本 skill 的验证机制只写「用什么方法、看什么信号」） |

定价数字和渠道价格没有来源就写 `No data`，不编；对外发布、收费开通、真实用户接触要先得到授权。
