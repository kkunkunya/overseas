# 辅源笔记模板

写新笔记时对照这个结构。六段是脚手架——资料没内容的段写一行"补洞"或"无"即可，别灌水。目标是 AI 一眼定位 + 与赫兹主源对齐，不是还原原文。

---

## 标题

```
# {作者}：{主题短句}
```

例：`# Marc Lou：一封冷邮件验证出第一个 $4k MRR 客户`

## 来源头（固定 4 行）

```markdown
> 来源层级：**辅源**，不覆盖赫兹主源（ADR-0001）。
> 视频/文章：{作者}，*{标题}*（{URL}）
> 用法：{一句话说清对接哪步/哪篇赫兹，或补什么洞}。
> 配套：{若与库内其他笔记交叉，点名文件路径}（无则删此行）
```

- 赫兹本人作品不进笔记层（进 `原文/`），所以这里默认 `辅源`。
- 「用法」是检索锚点：写清这资料在知识库里扮演什么角色。

## 一句话概念

```markdown
## 一句话概念

{核心主张，1–3 句。抓作者最想让你记住的那条规则，不写背景废话。}
```

## 速查表 / 流程图

```markdown
## {要点速查 / 真实流程 / 渠道速查}

{二选一或合一：}
{A. 多个并列要点 → markdown 表格，列：# / 要点 / 后果或收益 / 解法或动作}
{B. 有先后顺序 → ```text 流程框图```}
```

表格优先——AI 检索时表格比段落好定位。流程类内容（如"先卖再做"的步骤）用框图。

## 可复用细节

```markdown
## 可复用细节

### 1. {要点名}
- {可直接照做的动作，祈使句}
- {案例数字/边界条件}

### 2. {要点名}
...
```

每个要点展开成"能照着做"的动作，不是"作者说了什么"的复述。带具体数字、阈值、话术结构。

## 与赫兹主源对接

```markdown
## 与赫兹主源的对接

| {资料观点} | 赫兹对应 | 关系 |
|-----------|---------|------|
| {观点1} | `原文/N-步骤/编号-标题` | 一致 / 互补 / 补洞 / 冲突 |
```

- **一致**：两源说同一件事，互证。
- **互补**：赫兹给框架，辅源给案例（或反过来）。
- **补洞**：赫兹没覆盖，辅源补上（如冷邮件 pipeline 赫兹偏少）。
- **冲突**：两源说法矛盾——**一律以赫兹为准**，笔记里写明冲突点和取舍理由。

没对应点就写一行："本资料主题赫兹原文未覆盖，作补洞用。" 别硬凑表格。

## 防止误用

```markdown
## 防止误用

- {适用边界}：这个方法只在什么条件下有效
- {误读警告}：常见误读和纠正
- {数字归位}：作者案例的数字是结果不是承诺，复制前过赫兹 018 / 自己重算
```

3–6 条。这是让 AI 检索时不照搬误用的护栏。

## 可检索关键词

```markdown
## 可检索关键词

`关键词1` `关键词2` `英文术语` `中文术语` `作者名` `方法名`
```

中英混放，包含：作者名、核心方法名、所有出现的术语（中英）、行业/人群词。这是给 AI 检索的索引袋——想全。空格分隔的反引号块。

## 完成后三处索引（别漏）

1. 该步 `_本步导航.md`「我整理的笔记」加一行
2. `CONTEXT.md` 加术语条目（仅当有新术语/等价映射时）
3. `README.md` 笔记列 + 原始链接（仅当该步首篇或新增出处时）
