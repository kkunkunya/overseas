01 / 1-选方向回看基础

先确认顾客要办什么事

什么时候启动：新产品或需求判断出现新证据；已有网站只补影响当前决定的缺口。

负责入口：direction-validator
展开：准备什么、怎么做、做完去哪
准备什么
用户原话、当前替代品、网站承诺、付费理由。
怎么做
  1. 把人群、发生场景、想完成的任务写成一句话。
  2. 比较现有替代方案哪里不方便；指出本产品交得出的结果。
  3. 选一个最危险的假设，设计能观察使用或付费意愿的验证。
交出什么
客户任务与价值承诺卡。
怎么知道做对了
区分真实行为、访谈表达和自己的猜测；网站已建好不等于需求已成立。
工具与实际执行
先使用已有资料和工具；需要采集或写代码时交具体产品仓。

做完去哪 → 词与页面；已建站则带着未知项进入上线准备。

04 / 5-变现支付现在准备

把付钱和会员权益接成一条线

什么时候启动：付费产品已有会员系统但还没接支付；改变套餐或收费方式时重查。

负责入口：seo-readiness-audit
展开：准备什么、怎么做、做完去哪
准备什么
套餐、价格/币种、收费周期、权益、退款取消口径、选定支付服务。
怎么做
  1. 列出未付费、付款处理中、已付费、失败、取消和退款对应的权益。
  2. 准备与实际服务一致的价格说明、服务条款、隐私及退款/取消政策；按目标地区和选定支付服务当前要求核查，不套用通用法律结论。
  3. 把订单、服务端支付确认、用户账户和权益的对应关系交工程实现。
  4. 在测试环境检查成功、失败、重复通知、延迟通知和取消退款后的结果。
交出什么
支付与会员权益交接单、测试记录。
怎么知道做对了
跳回成功页不等于收到钱；订单、支付记录与实际权益能对上。真实收款另有授权和验证。
工具与实际执行
调用选定支付服务对应的已安装skill并查其当前官方文档；代码、webhook、密钥在产品仓处理。

做完去哪 → 域名上线与正式环境复查。

06 / 3-SEO获客现在准备

让搜索引擎进得来、看得懂

什么时候启动：准备上线、刚上线、未收录或索引异常；每次修复后回到同条件复测。

负责入口：seo-readiness-audit
展开：准备什么、怎么做、做完去哪
准备什么
产品/仓库与owner、正式/预览URL、公开页面清单、初始HTML、浏览器页面和站点地图。
怎么做
  1. 先记录产品、环境和公开/私有页面边界，再查访问状态并比较初始HTML与渲染后的关键内容。
  2. 核对robots、noindex、canonical、sitemap和内链是否表达一致的页面角色。
  3. 逐条写问题、证据、影响、确定程度、修复owner与同条件复测；工具没读到的内容标未知，不当作网站故障。
交出什么
按阻塞/可后置排序、带复测条件的审计单。
怎么知道做对了
能复现每个问题；修复后用同一URL、环境和观察条件回查。不把robots/noindex当登录保护。
工具与实际执行
浏览器和HTTP检查取证；大量页面才选批量抓取，不能用一次工具失败判网站故障。

做完去哪 → 首批抓取和索引观察；缺工具或权限时交“程序工具怎么接进来”。

08 / 6-复盘增长现在准备

上线前先装好记账本

什么时候启动：准备上线或开始一个新渠道；不能等数据丢了才设计记录。

负责入口：product-growth-review
展开：准备什么、怎么做、做完去哪
准备什么
用户任务路径、订单/会员模型、分析工具、环境、测试数据规则与数据使用约束。
怎么做
  1. 先写要做的决定，再倒推访问、开始、完成、注册、付款等必要事件。
  2. 上线前明确收集用途、必要字段、适用的同意机制与许可记录；区分账户通知和营销许可，未来发信不能倒填历史同意。
  3. 定义每个事件什么时候触发、怎样去重、用什么口径统计，并把正式、测试、未接通和零值分开。
  4. 在测试环境沿真实路径触发，核对事件、订单和会员记录，排除内部测试；模拟样本明确标“模拟”。

怎么知道做对了

工具与实际执行

做完去哪 → 上线观察与增长复盘，按同一口径定位最早瓶颈。
