# ADR-0015: 参考站先行选词，交付付费站清单与核心/长尾词

- status: accepted
- date: 2026-08-23

## 背景

旧选词顺序是「从任务假设或脑暴扩词 → SERP → 短名单 ≤3 → 场景卡」。执行中容易先堆一堆说法，再回头猜哪个站在赚钱；电商、广告站和没有付费入口的内容站也会混进样本。当前路径是做出海付费 App（订阅或明确付费意愿），不是做电商或纯广告站。

量/KD 必须取证、禁止编造这一条仍然成立。需要改的是**先看谁已经靠付费活下来**，再从这些站收词。

## 决策

1. **参考站先行**：选词从目标领域的参考网站开始。Agent 用多个模型并列参考站，整理成带超链接的 Markdown；人自己看 Title、Description 和付费入口，并把准备深挖域名的 Semrush（流量、反链、流量占比、自然关键词）导出交给 Agent。SEO 概况和挖词只读这份导出，不编造、不改用别的数顶上。
2. **只把付费站当正式样本**：正式清单收订阅、买断或明确付费墙的产品站 / App 站；Semrush 意图可标 C（Commercial）的词所指向的站优先。电商和纯广告站不进正式清单。
3. **先看成功根源，再挖词**：确认流量规模、反链量级和流量占比后，才从这些站收词。新手优先 **KD < 50** 且搜索量较好的词；品牌词可作为品类参考，不去抢别人的品牌首页。
4. **交付形状**：3 个核心关键词 + 10–15 个长尾词，再去 Instagram / Reddit / TikTok 反查需求，然后做产品。
5. **证据硬、阈值软**：月搜与 KD 仍须取自工具或人贴的数，禁止编造；KD 50 和量级都是过滤器，不是全有或全无门槛。

## 理由

- 付费站已经证明有人愿意付钱；从它们的词和流量结构反推，比从空想扩词更接近可做的 App。
- 多模型找站是为了覆盖面，不是为了投票定方向；人审商业逻辑和 SEO 才是闸门。
- 旧 SOP 的「先词后站」会把时间和注意力耗在没有付费模式的词上。

## 继承 ADR-0007

- 选词交付必须尽力取月搜与 KD（或明确标注的降级线索），写清厂商、日期、地区；禁止编造。
- 数字是过滤器不是宗教；SERP 和真实付费逻辑仍硬于裸 KD。
- AITDK 等扩词器只提供说法，不含量/KD。
- 新手 KD 参考带由「0–30」改为「优先 < 50」；更低仍然更容易，更高仍可做但默认当更强竞争。

## 后果

- `vertical-keyword-loop`、选词 SOP、第一步作战卡与 `ask-overseas` 按「站 → 人审 → 词 → 社区 → 产品」路由。
- ADR-0007 由本 ADR 取代；旧 SOP 归档为 `1-选方向/归档-SOP-垂直选词人机闭环.md`。
- 历史选词轮次（tattoo 等）保留为对照，不再当现行剧本。
