# 卖空气验证要点（赫兹 015 主源 × 028/029 补强）

> 运行规则：每次进入卖空气验证前读本文件，再开始做页面或触达。
> 权威次序：赫兹原文为主；本文件是把赫兹 015/028/029 落成可执行顺序的项目整理，不冒充作者原话。

## 1. 赫兹《卖空气验证需求》(015) 的核心动作

卖空气 = 预售：告诉用户这是什么产品、解决什么问题、定价多少，看有多少人愿意付费，再决定是否真正生产。

Pieter Levels《MAKE》的例子：没等书写完，先写部分内容和大纲 → 搭简单落地页 → 放预售标语 → 预售期就赚到钱并验证市场。

可上线营销 Landing Page 的步骤：

1. 写产品预售营销文案，尤其列出要解决的问题和 3 个卖点；
2. 用 AI 生成 Landing Page；
3. 接入 Stripe 支付功能；
4. 购买 Google 关键词广告或其他宣传渠道，关注转化率数据。

原文强调：做产品最重要的不是功能有多炫，而是有人愿意为它买单。千万别等产品开发完再去验证需求，那样浪费时间。最有效的方式是敢于卖空气——在产品没成型时直接抛出想法，定真实价格，看有没有人愿意提前付费。如果没有，果断止损。

## 2. 赫兹《基于人群找细分需求》(028)：先定人群再谈承接

小排老师的经典问句：什么人，在什么场景下，愿意花多少钱，解决什么问题。第一点就是「什么人」，所以先确定人群，再去看需求。

同一类产品面对的人群差异非常大。卡住一个细分人群，把场景做到极致，那就是刚需，这部分愿意付费，收益也较可观。

找准人群后推广变得更易：你知道他在哪（社区）、看什么内容（关键词）、被什么打动（痛点）。文案、SEO、广告都更精准，不再广撒网。

找人群 → 拆场景 → 找痛点 → 做极致 → 精准推广，懂一小撮人并能高效触达。

对本 skill 的执行含义：Landing Page 的文案、3 个卖点和触达平台都由「人群 × 场景 × 痛点」决定，不是先做页面再找流量。

## 3. 赫兹《需求的痛点决定了转化率》(029)：痛点等级决定付费意愿

需求痛点有等级，等级越高付费意愿越强、转化率越高：

1. 娱乐型：好玩、新鲜、猎奇，不用也没影响。流量可能大但付费意愿通常不强。
2. 兴趣型：有兴趣但非刚需，容易被平替，复购不一定高。
3. 效率型：帮用户省时间/省人力/省成本。算账发现省钱省时，付费转化明显提高。
4. 赚钱型：用了有机会直接赚到钱。用户发现花 30 美元能赚 300 美元，非常愿意用，转化率更高、客单价更高、更能接受涨价、更易长期订阅。
5. 强刚需：不解决就难受，直接影响收入、工作、生存。核心不是提升而是必须。

对本 skill 的执行含义：先判断当前方向属于哪一级；赚钱型与强刚需最容易验证付费意愿。核心承诺、价格和触达话术都要承接这个赚钱或强痛点时刻，不能写成「一个好玩的工具」。

## 4. 赫兹《用 Discord 挖掘需求》(019)：社区触达的安全姿势

Discord 对早期产品是被低估的增长渠道，可做 4 件事：挖掘需求、验证需求、推广产品、提升转化。

推广最容易踩雷：

- 不推荐：大规模冷 DM、在禁止推广的频道发链接（会被清理）、明显挖竞品用户。陌生人 DM 一天 15 个左右就可能掉登。
- 推荐：先参与讨论建立信任 → 回答问题时顺带给方案 → 在 Showcase/Feedback 频道展示案例 → 自然说「如果你正好需要 XX，我之前做了个小工具，有需要我可以发你看看」。不打扰不强推，转化率反而更高。

提升粘性与转化：主动回答问题（尽量 24 小时内）、定期发布更新、把高频问题沉淀成文档或 Bot 回复、给社群用户专属内测/优惠码/优先体验。

对本 skill 的执行含义：触达顺序是「先贡献价值、再自然提产品」，不是「先发链接」。各社区同理。

## 5. 卖空气验证的顺序闸门（项目整理，非赫兹原话）

赫兹给出原则，下面是把它落成可执行顺序的闸门，用于把失败归到正确位置：

1. 问题与人群：是否承接一个赚钱型或强痛点时刻？（028/029）
2. 承诺可懂：陌生人 3 秒内能否理解「输入什么、得到什么结果、为什么重要」？
3. 价格真实：是否放了一个不便宜到熟人鼓励、也不贵到无人试的价格？（015）
4. CTA 与埋点：是否有购买/预订入口，且只收集会改变决策的事件？
5. 流量合格：是否真的送到目标人群面前，而不是泛围观者？
6. 真实行动：是否出现输入真实数据、询价、预订或付款？

任何前置项失败，后面的流量或曝光不能抵消它。

## 6. 失败归因表（项目整理）

| 结果 | 归因 | 不能推出 |
|---|---|---|
| 没人看到 | 流量/触达失败 | 需求不存在 |
| 有人看但没人输入 | 表达、信任或承接可能失败 | 一次即可判死刑 |
| 输入但不买 | 价值、价格或付费时刻可能失败 | 已有需求但产品不行 |
| 演示当前流程并给脱敏样例 | 强问题证据 | 一定会付款 |
| 愿意复用、询价、交订金或付款 | 商业证据 | 已找到可规模化流量 |

## 7. 与方向验证的接法

```text
direction-validator 拍板 go
→ 写验证合同（截止/预算/成功行动/停止条件）
→ 确认痛点等级与核心承诺（029/028）
→ 做一页可丢弃 Landing Page（015）
→ 放真实价格与 CTA（015）
→ 送一小股合资格流量（019 安全姿势 + community-outreach.md）
→ 观察真实行动并归因
→ build / revise / reject
```

只在没有真实行动信号时不前进；有信号也不直接跳到完整产品，而是先做最小可用 MVP。
