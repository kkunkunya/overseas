# mvp-validation / 卖空气验证与最小触达

本 skill 接在 `direction-validator` 之后：方向已经过「需求 → 意图 → 竞争 → 承接 → 触达 → 流量 → 变现」闸门拍板为 `go`。下一步不是写产品代码，而是「卖空气」——用一页可丢弃的 Landing Page、真实价格、真实 CTA 和一小股合资格流量，测试陌生人是否理解方案、接受价格并采取行动。

赫兹《卖空气验证需求》(015) 是本 skill 的主方法源：先做概念预售，看有没有人愿意付费，再决定是否真正生产。赫兹《基于人群找细分需求》(028) 和《需求的痛点决定了转化率》(029) 决定承接承诺和触达方向。触达通道与合规顺序见 `references/community-outreach.md`。

## 0. 先确认前置闸门已通过

本 skill 假设 `direction-validator` 已产出：

- 一个明确人群 × 具体场景 × 重复任务；
- 一个可反驳的缺口命题（输入 → 结果 → 可观察变化）；
- 至少两类相互独立的证据；
- 一个可复现的冷流量/真人触达入口；
- 用户已拍板 `go to validation`（允许做可丢弃 Landing Page，尚未批准完整产品开发）。

任何一项缺失，回到 `direction-validator`，不要用「先把页面上线再说」跳过验证合同。

完成判据：能一句话写清本轮要验证的付费假设和最早失败信号，且不需要先写任何产品功能代码。

## 1. 写验证合同，防止验证变成拖延

卖空气不是为了「把页面做漂亮」，而是为了拿一个会改变下一步决策的真实信号。上线前先写明：

- 本轮截止时间：最多 7–14 天，到期必须决定 build / revise / reject；
- 现金预算：页面前端成本、域名、小额广告预算上限；
- 合资格访问上限：例如 50–100 个目标人群访问；
- 成功行动（不能只写"有人说感兴趣"）：至少 3 人提交真实项目参数 + 至少 1 人点击购买/愿意预付；订金或付款是更强证据；
- 停止条件：曝光不足先换流量，曝光够但无人行动则归因到承接/价格/痛点；
- 到期必须做的决定：build 最小可用 MVP / revise 承接或切口 / reject 方向。

完成判据：验证合同已落盘，失败时不会用「再优化一下页面」代替结论。

## 2. 确认痛点等级与核心承诺

按赫兹 029，痛点等级直接决定转化率和付费意愿：

| 等级 | 特征 | 付费意愿 | 本项目适配 |
|---|---|---|---|
| 娱乐型 | 好玩、新鲜、不用也行 | 弱 | 不做 |
| 兴趣型 | 有兴趣但非刚需 | 弱-中 | 谨慎 |
| 效率型 | 省时间/省人力/省成本 | 中 | 可做 |
| 赚钱型 | 用了能直接赚更多钱 | 强 | 首选 |
| 强刚需 | 不解决就难受/影响收入 | 极强 | 可做 |

amigurumi pricing calculator 属于赚钱型：卖家算清售价和真实时薪，直接关系到定价和利润。核心承诺必须承接这个赚钱时刻，不是「做一个计算器」。

写一行核心承诺，用户能在 3 秒内理解：

```text
For {人群} who {场景/重复任务},
{页面名} shows {可观察结果} after {具体输入},
so they can {赚钱/省时决策}.
```

例：For amigurumi sellers who want to price a finished doll, the Amigurumi Pricing Calculator shows the break-even price, suggested price, and real hourly wage after materials, time, and selling fees, so they can stop underpricing and know if a commission is worth taking.

完成判据：核心承诺承接一个赚钱或强痛点时刻，且能用用户原话重述，不是功能清单。

## 3. 做一页可丢弃 Landing Page，不做产品

页面只做销售/意图实验，不先做账号、后台、数据库、完整计算逻辑。最小结构见 assets/landing-page-checklist.md。关键组成：

1. 一句话问题 + 3 个卖点：用用户原话写痛点，不要营销腔；
2. 示例输入与结果展示（「扫一下得到什么」）：放一组真实参数（如材料 $8、6 小时、Etsy 费率）和对应结果卡——现金成本、完整成本、建议售价、真实时薪、预计利润。用户要能一眼看到「把我的娃娃信息放进去会得到什么」，不必先注册或先点按钮；
3. 一个真实价格：免费即时计算 + 一个明确 Pro 报价（如 $7 一次性），价格是待测假设不是定论；
4. 一个主要 CTA + 一个次要 CTA：主 CTA = 购买/预订；次 CTA = 提交真实项目或留邮箱；
5. 信任与边界说明：明确交付什么、不交付什么、退款/隐私政策雏形、联系方式；
6. 埋点（只收集会改变决策的事件）：到达 → 开始输入 → 完成输入 → 查看结果 → 点击购买 → checkout → 付款。热图和 SEO 建议是诊断工具，不是成功信号。

「扫娃娃得到什么」的展示策略：当前无图像识别链路时，用「填参数看结果」的静态示例即可——展示一组真实输入和它产生的结果卡，让用户预判自己的娃娃会得到什么。只有当「拍照即识别尺寸/类型」被反复要求、且能人工跑通准确度时，才升级为图像识别 Demo；不因技术可做就反推需求。

明确不做：账号系统、社区、pattern marketplace、库存、订单管理、移动 App、完整计算器后端。这些只在真实行动信号出现后才考虑。

完成判据：页面可在手机上走完一次「读示例 → 理解结果 → 看到 CTA 和价格」，且没有需要先登录或先付费才能看的墙。

## 4. 最小价格实验：先问「愿不愿付」再问「付多少」

在免费即时价值之外只放一个明确付费承诺、价格和入口，目的是判断是否愿付和为何愿付，不是一次性设计完整套餐。赫兹 015 提醒：价格不能太低，太低时熟人可能出于鼓励支持，不反映真实付费意愿。

- 免费层：即时计算、看结果；
- Pro 层：保存项目、PDF/报价导出、Etsy/craft fair fee presets——先作为承诺写在页面上，不必先实现；
- 若用户点购买但 Pro 未实现：人工邮件交付或诚实退款，记录为「有付费意愿但需验证交付」；
- 不做月费/年费/多档套餐，直到出现重复购买或主动询价再升级。

完成判据：页面上只有一个价格和一个购买入口，没有复杂套餐。

## 5. 触达：Reddit 为主，X 为备，许可式研究

完整触达顺序、平台特性、合规边界见 references/community-outreach.md。本节给最小骨架：

1. 先选平台：默认 Reddit（crochet/amigurumi 有 r/Amigurumi、r/crochet、r/Etsy、r/crochetbusiness 等公开社区，定价讨论活跃）；X（Twitter）为备选（maker/crochet 圈有活跃创作者，但更需要已有账号信任）；Discord 作为有 crochet 社群时的补充；Facebook 老平台群组活跃但规则更严；
2. 社区调研必须走 Chrome 登录态：用 Codex Chrome 插件复用用户登录，读版规、固定帖、账号门槛、研究/推广限制；
3. 先观察后参与：读近期定价帖、痛点原话、替代方案，记录到触达记录卡（assets/outreach-record.md）；
4. 公开上下文回复在前：只回复与原帖直接相关的人，先给一个有帮助的观察或追问，相关时才自然说明自己做了什么；
5. 征得许可再私聊：公开回复得到回应后，再问能否私聊或看一个简单定价页；
6. 记录行动证据：每次触达记 URL、对象资格、消息内容、回应、行动结果。

禁止：伪装卖家经历、群发陌生私信、隐藏商业身份、被过滤后反复重发、索取未脱敏订单数据。被平台过滤或版规禁止 = 渠道失败，不是需求失败；合资格用户看到方案后仍不行动，才是需求/承接/变现的反证。

本对话只做 skill 与触达计划，不真正发帖或私信；实际触达需 Kun 明确授权，在下个对话执行。

完成判据：触达记录卡已列出本轮 3–5 个目标社区、触达上限、合规检查结果和首条消息草稿，且没有「先群发一批试试」的冲动。

## 6. 用顺序闸门归因失败，不把流量当成功

| 结果 | 归因 | 不能推出 |
|---|---|---|
| 没人看到 | 流量/触达失败 | 需求不存在 |
| 有人看但没人输入 | 表达、信任或承接可能失败 | 一次即可判死刑 |
| 输入但不买 | 价值、价格或付费时刻可能失败 | 已有需求但产品不行 |
| 演示当前流程并给脱敏样例 | 强问题证据 | 一定会付款 |
| 愿意复用、询价、交订金或付款 | 商业证据 | 已找到可规模化流量 |

搜索数据负责选词，真实点击、使用、询价和付款负责验证站。上线后有流量无转化，先复查搜索意图、页面承接和价格路径，不把流量当成功。

完成判据：每个失败结果能归到具体闸门，有唯一下一步（换流量 / 改页面 / 改价格 / 改切口 / reject）。

## 7. 人机交接与停止条件

Agent 负责：页面文案草稿、示例输入与结果卡、埋点方案、社区调研、触达记录卡、归因建议。Kun 决定：策略偏好、预算、对外动作授权、最终 build/revise/reject。

只询问会改变当前 frontier 的决定，给推荐答案与理由，每轮最多补一次关键未知后交还用户。方向尚未出现真实行动信号前，不开始产品代码项目；为取得强信号而制作的可丢弃概念页/人工交付不算重产品开发。

停止条件：验证合同到期时必须做决定。若新增信息不会改变 build/revise/reject，停止优化页面并执行决定。不为「再验证一轮」无限延长。

## 8. 阶段边界：不提前建设

当前只取验证段：人群与痛点 → 核心承诺 → 触达合资格用户 → 真实行动信号。不要提前建设：

- 自动化、Agent 后台、复杂运营系统（先运行再自动化，见 1-选方向/AI时代公司35步-阶段化学习.md）；
- 涨粉、内容矩阵、大号运营（没有合资格用户行动前不替代验证）；
- Creator 股权/长期分成（没有明确承诺、归因和单位经济前不谈）；
- 完整 SaaS、平台、生态、多产品组合（单点价值成立前不做）。

这些是验证通过、MVP 跑通、有真实付费后的后续阶段，不是当前待办。

## 9. 学习新方法时更新，不自创规则

只有用户明确要求精读某篇赫兹/辅源材料时，走学习分支：提炼入口、执行顺序、可观察判据、工具路由和反例；标注哪些是作者明确规则、哪些是案例或归纳；用一个真实候选试跑判断是否改变流程；确认有效的增量写入 references/，并在交付时说明变更。没有可观察判据的新观点只记为学习笔记，不升级为 skill 规则。
