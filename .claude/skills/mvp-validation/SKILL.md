# mvp-validation / 卖空气验证与最小触达

本 skill 接在 `direction-validator` 之后：方向已经过「需求 → 意图 → 竞争 → 承接 → 触达 → 流量 → 变现」闸门拍板为 `go`。下一步不是写产品代码，而是「卖空气」——用一页可丢弃的 Landing Page、真实价格、真实 CTA 和一小股合资格流量，测试陌生人是否理解方案、接受价格并采取行动。

赫兹《卖空气验证需求》(015) 是本 skill 的主方法源：先做概念预售，看有没有人愿意付费，再决定是否真正生产。赫兹《基于人群找细分需求》(028) 和《需求的痛点决定了转化率》(029) 决定承接承诺和触达方向。赫兹《用 Discord 挖掘需求》(019) 给社区触达的安全姿势。触达通道与合规顺序见 `references/community-outreach.md`。

## 0. 先确认前置闸门已通过

本 skill 假设 `direction-validator` 已产出：

- 一个明确人群 × 具体场景 × 重复任务；
- 一个可反驳的缺口命题（输入 → 结果 → 可观察变化）；
- 至少两类相互独立的证据；
- 一个可复现的冷流量/真人触达入口；
- 用户已拍板 `go to validation`（允许做可丢弃 Landing Page，尚未批准完整产品开发）。

任何一项缺失，回到 `direction-validator`，不要用「先把页面上线再说」跳过验证合同。

完成判据：能一句话写清本轮要验证的付费假设和最早失败信号，且不需要先写任何产品功能代码。

## 1. 写验证合同，防止验证变成拖延

卖空气不是为了「把页面做漂亮」，而是为了拿一个会改变下一步决策的真实信号。上线前先写明：

- 本轮截止时间：最多 7–14 天，到期必须决定 build / revise / reject；
- 现金预算：页面前端成本、域名、小额广告预算上限；
- 合资格访问上限：例如 50–100 个目标人群访问；
- 成功行动（不能只写"有人说感兴趣"）：至少 3 人提交真实项目参数 + 至少 1 人点击购买/愿意预付；订金或付款是更强证据；
- 停止条件：曝光不足先换流量，曝光够但无人行动则归因到承接/价格/痛点；
- 到期必须做的决定：build 最小可用 MVP / revise 承接或切口 / reject 方向。

完成判据：验证合同已落盘，失败时不会用「再优化一下页面」代替结论。

## 2. 确认痛点等级与核心承诺

按赫兹 029，痛点等级直接决定转化率和付费意愿：

| 等级 | 特征 | 付费意愿 |
|---|---|---|
| 娱乐型 | 好玩、新鲜、不用也行 | 弱 |
| 兴趣型 | 有兴趣但非刚需 | 弱-中 |
| 效率型 | 省时间/省人力/省成本 | 中 |
| 赚钱型 | 用了能直接赚更多钱 | 强 |
| 强刚需 | 不解决就难受/影响收入 | 极强 |

先判断当前方向属于哪一级；赚钱型与强刚需最容易验证付费意愿。核心承诺必须承接这个赚钱或强痛点时刻，不是「做一个 XX 工具」。

写一行核心承诺，用户能在 3 秒内理解：

```text
For {人群} who {场景/重复任务},
{页面名} shows {可观察结果} after {具体输入},
so they can {赚钱/省时决策}.
```

完成判据：核心承诺承接一个赚钱或强痛点时刻，且能用用户原话重述，不是功能清单。

## 3. 做一个 product-shaped MVP：完整承诺，最小兑现

AI 让单点功能和静态文案更容易复制。验证物仍可丢弃，但不应退化成只有一张功能清单的 Landing Page。先做一个 **product-shaped MVP**：让用户看见完整的工作成果和相邻步骤，同时只实现其中决定购买信心的最小一段。页面结构与检查项见 assets/landing-page-checklist.md；当需要判断 AI 时代的承诺边界时，读 references/ai-era-product-shaped-mvp.md。

1. **Outcome first**：首屏写 `{谁} 在 {高代价时刻}，输入 {真实素材} 后得到 {可行动的产物/判断}，从而 {避免损失/赚到钱}`。避免只承诺“AI 帮你做 X”。
2. **展示完整 job，而不是凑功能**：用 workflow 图或交付物样例说明用户如何从输入走到决策、沟通或交付。只展示同一用户在同一任务中紧接着会发生的相邻步骤；不把想象中的功能拼成伪工作台。
3. **兑现核心 verdict / artifact**：必须让用户看见一组真实输入与具体结果，且核心一步能通过交互 demo 或 concierge（人工交付）兑现。可用脱敏的报告、报价单、比较表、效果图或行动建议，而非只有数字卡片。
4. **诚实区分状态**：`Available now`、`Founding-member concierge` 与 `Planned` 分开标出。未实现能力可以作为预约后的方向收集意见，不能营造已经可用的印象。
5. **一个真实价格与两条 CTA**：主 CTA 是购买/预订这个具体结果；次 CTA 是提交真实项目。免费 demo 可以降低理解门槛，但不能替代真实价格实验。
6. **信任与边界**：说明数据来源或人工核验、交付什么/不交付什么、隐私、退款与联系方式。它要回答“为何我不自己问一次 ChatGPT”。
7. **埋点**：到达 → 查看工作流/样例 → 开始输入 → 完成输入 → 查看结果 → 提交真实任务 → 点击购买 → checkout → 付款。热图和 SEO 建议只用于诊断。

MVP 的最小性由“能否可信地跑通一个 end-to-end job”决定，不由页面元素或自动化数量决定。账号、后台、数据库和全面自动化仍等待真实重复使用再开发。

完成判据：手机上能走完「看见完整结果承诺 → 检查一份可信样例 → 用真实输入取得核心结果/申请人工交付 → 看到价格和 CTA」；未实现项状态明确。

## 4. 最小价格实验：先问「愿不愿为结果付」再问「付多少」

只放一个明确的付费结果、价格和入口，目的是判断愿不愿付及其原因，不是一次性设计套餐。赫兹 015 提醒：价格不能太低，太低时熟人可能出于鼓励支持，不反映真实付费意愿。

- 免费层：看样例、理解工作流或取得有限 demo；
- 付费层：一个具体 artifact / verdict / concierge 交付，或首发产品的明确预订；
- 只有用户反复要求的相邻工作步骤才写入 `Planned`，并标明未实现。

不做月费/年费/多档套餐，直到出现重复购买、复用或主动询价再升级。

完成判据：页面上只有一个价格和一条购买路径；用户知道这笔钱现在能得到什么，哪些还在计划中。

## 5. 触达：以赫兹推荐的平台为准

**硬规矩：触达前必须先确认反馈回路通。** 带参数链接（UTM / 来源标记）+ 能测到「有没有人真用」（到达 → 输入 → 结果 → 点击购买）。没埋点不准触达——发了等于白发，是最常见的验证缺口。

赫兹推荐的触达渠道：朋友圈/社群宣传、Google 关键词搜索广告或其他宣传渠道（015）；Reddit、小红书、Twitter 等社区（017）；Discord（019）。按当前方向的目标人群在哪、规则是否允许来选平台，不硬编码某一平台。完整触达顺序、平台特性、合规边界见 references/community-outreach.md。本节给最小骨架：

1. 先选平台：看目标人群在哪些赫兹推荐的社区/渠道活跃，逐一检查版规、账号门槛、研究/推广限制；
2. 社区调研走 Chrome 登录态：用 Codex Chrome 插件复用用户登录，读版规、固定帖、账号门槛；
3. 先观察后参与：读近期相关帖、痛点原话、替代方案，记录到触达记录卡（assets/outreach-record.md）；
4. 公开上下文回复在前：只回复与原帖直接相关的人，先给一个有帮助的观察或追问，相关时才自然说明自己做了什么；
5. 征得许可再私聊：公开回复得到回应后，再问能否私聊或看一个简单页面；
6. 记录行动证据：每次触达记 URL、对象资格、消息内容、回应、行动结果。

完成判据：触达记录卡已列出本轮 3–5 个目标社区、触达上限、合规检查结果和首条消息草稿。

## 6. 用顺序闸门归因失败，不把流量当成功

| 结果 | 归因 | 不能推出 |
|---|---|---|
| 没人看到 | 流量/触达失败 | 需求不存在 |
| 有人看但没人输入 | 表达、信任或承接可能失败 | 一次即可判死刑 |
| 输入但不买 | 价值、价格或付费时刻可能失败 | 已有需求但产品不行 |
| 演示当前流程并给脱敏样例 | 强问题证据 | 一定会付款 |
| 愿意复用、询价、交订金或付款 | 商业证据 | 已找到可规模化流量 |

搜索数据负责选词，真实点击、使用、询价和付款负责验证站。上线后有流量无转化，先复查搜索意图、页面承接和价格路径，不把流量当成功。

完成判据：每个失败结果能归到具体闸门，有唯一下一步（换流量 / 改页面 / 改价格 / 改切口 / reject）。

## 7. 人机交接与停止条件

Agent 负责：页面文案草稿、示例输入与结果卡、埋点方案、社区调研、触达记录卡、归因建议。用户决定：策略偏好、预算、对外动作授权、最终 build/revise/reject。

只询问会改变当前 frontier 的决定，给推荐答案与理由，每轮最多补一次关键未知后交还用户。方向尚未出现真实行动信号前，不开始产品代码项目；为取得强信号而制作的可丢弃概念页/人工交付不算重产品开发。

停止条件：验证合同到期时必须做决定。若新增信息不会改变 build/revise/reject，停止优化页面并执行决定。不为「再验证一轮」无限延长。

## 8. 学习新方法时更新，不自创规则

只有用户明确要求精读某篇赫兹/辅源材料时，走学习分支：提炼入口、执行顺序、可观察判据、工具路由和反例；标注哪些是作者明确规则、哪些是案例或归纳；用一个真实候选试跑判断是否改变流程；确认有效的增量写入 references/，并在交付时说明变更。没有可观察判据的新观点只记为学习笔记，不升级为 skill 规则。
