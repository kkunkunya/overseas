# vertical-keyword-loop / 垂直选词人机闭环

把「有人搜的窄任务」收成可拍板的短名单与灯色。方法可移植：不依赖某一仓库路径、某一作者教主或固定国家。

## 你的角色

Agent 取证与建议；用户建立体感并最终拍板。禁止编造月搜/KD。

## 直线流程

```text
找词 → 取证 → 短名单(≤3) → 用户开网页+插件 → 场景还原 → 灯色拍板
```

任一步缺证据就标缺口，不跳步假装已验证。可循环开下一轮，不并行深挖 >1 个主词。

**方向铁律（ADR-0008，2026-08-09）**：旧需求薄弱点 > 新需求；不做纯计算器；欧美红海 → 东南亚/中东等蓝海市场优先；体感是硬门（Kun 不熟悉/无感不硬选）。**协作契约：找到词先沟通再深挖，让 Kun 亲自看；不独自跑完整条链。**

### 0. 已跑通三波流程（Kun 确认）

1. 第一波：发现和筛选（批量候选 → 垂直/数据/SERP 门粗筛）
2. 第二波：打开网站 + AITDK 分析（功能/定价/获客；AITDK 块锚定读流量，域级 vs 页级分开标；traffic.cv 核对）
3. 第三波：YouTube/Instagram 了解关键词真实场景（用户怎么搜、怎么用、痛点；写场景卡）
4. 最后：Kun 决定是否做产品；go 由 Kun 拍

### 0.1 快速方向发现循环（第 8 轮实践固化，Kun 确认有效）

> 找方向的早期阶段（还没定具体词时）用这套协作节奏，避免 Agent 独自跑完整条链。

```text
扫描（社媒+扩词+候选池） → 给候选池让 Kun 圈范围 → 取证（KD/SERP/社媒） → 收敛到具体词 → 给词让 Kun 开 AITDK 筛查 → 一起定产品切入点
```

要点：
- **给候选池让 Kun 圈范围**：不一次给 60 个词，而是给按原则预筛过的候选池（人群×国家×场景），让 Kun 用体感圈方向，Kun 也可自己加线（例：第 8 轮 Kun 加「肖像」线）。
- **取证后再收敛**：Kun 圈完方向后，Agent 对候选做 KD/SERP/社媒取证，按蓝海标准收敛到 ≤5 个具体词。
- **给词让 Kun 开 AITDK 筛查**：每词附 Google 搜索 URL + 看什么（SERP 前排强弱、有没有可打的薄页、巨头锁没锁），Kun 打开后反馈，Agent 再做竞品表。
- **一起定产品**：筛查完，Agent 和 Kun 一起把「产品做成什么样」敲定（不是 Agent 单方面给方案）。

### 1. 找词（Seed）

**开场先问 Kun**（每轮固定，见 [seed-questions.md](assets/seed-questions.md)）：什么让你停不下来 / 你愿意免费帮谁 / 你每周最烦的麻烦事。**问题只触发兴趣，不考知识**——Kun 感兴趣就会自己去研究；答不出具体场景时，不硬选词。

**随手种子优先**：Kun 随时丢来的产品/推文/想法（例：Diluter Network、derouter、Testimonial.to）是最真实信号——**先记录进 `docs/kun-profile.md` 随手种子库，再按三标准快速初判**（需求真不真 → 词存不存在 → 竞品挤不挤 → 趋势涨不涨），判完告诉 Kun 值不值得查。注意：需求真 + 趋势真 ≠ 词存在（如 Diluter 搜索量≈0，是平台生意非 SEO 资产生意）。

**找到词先沟通再深挖**：一旦觉得找到词，先停下来与 Kun 沟通并让他自己去看（可给 1–2 个 URL）；Kun 看完再进深度调研，不独自跑完整条链。

收集 **5–15** 条英文任务短语，每条尽量附「谁 × 场合 × 任务」（用户语言可用中文备注）。

**社媒扫词（本轮固化，2026-08-09）**：ins / reddit / x / threads 是重要找词渠道，与 autocomplete/Ahrefs/SERP 并列。扫词时看：① 有没有真实讨论/提问；② 量级感觉（弱/中/强）；③ 有没有人在卖相关数字产品（谁、卖什么、怎么卖）。登录态平台用用户 Chrome 只读扫描，不点赞不评论不关注。需求人话信号：社媒有讨论 + KD 低 + 前排没做好 + 当地语言可搜 = 蓝海候选（不限东南亚）。

**蓝海标准（轻量，不过度设计）**：社媒有人问 + KD ≤ 10（或 No data + SERP 无强站） + 前排没做好（小站/薄页为主） + 当地语言可搜。

**Agent 默认可做：**

- 场景模板：`{scene} generator|maker|template|converter|checker|calculator` 等
- Google 自动补全 / 相关搜索 / PAA
- Google Trends：兴趣形状 + **多国对比** + related/rising（上升国可优先，不绑死美国）
- 公开社区检索（如 `site:reddit.com`）；需登录态时用用户 Chrome，遇墙停下让用户登录
- 打开 1–2 个结果站抄 H1/导航类目
- 网页扩词工具（如 AITDK Keywords）：**只扩说法，不当月搜**
- 词找站 / 站找词：搜词看谁在排；从站反推词

**用户补全（Agent 不便时）：** 无痕 SERP、SEO 插件读数、Trends 换国、登录态社区、粘贴词表/截图。

**完成：** 种子带来源；粗杀品牌锁死词、纯巨头功能大战场、用户已明确淘汰的方向。

### 2. 取证（准备进短名单的词）

每词尽量齐：

| 证据 | 做什么 | 记录 |
|------|--------|------|
| 真 SERP | 目标国 Google 前约 10 | 域名、页型（工具/文章/App/电商…）、强/薄 |
| 月搜 / KD | 可用的 SEO 工具或插件 | **厂商、日期、国家**；精确 / 线索 / No data |
| Trends | 目标国 ± 对比国；1y 或 5y | 涨/稳/尖刺；related |
| 付费线索 | 点进 3–5 个结果 | 定价、订阅、积分、询价 |
| 3 条具体更好 | 相对前排 | 写不出则承接闸门不通过 |

**纪律（硬）：**

1. **禁止编造**月搜/KD；没有就写 No data 或降级线索并标明性质。  
2. **SERP 优先于裸 KD**：KD 好看但前排全巨头 → 可淘汰；KD 略高但前排小站/薄页 → 可保留。  
3. **参考带**约月搜 1000+、KD 0–30：缩小池子用，**不是电门**——略偏可 `watch`；过线但 SERP 铁板/无付费仍可 `reject`。  
4. 不同厂商 KD **不可横比**。

详表与字段见 [metrics-and-lamps.md](references/metrics-and-lamps.md)（取证与灯色时读）。
SERP 块锚定 + AITDK/traffic.cv 爬取与记录纪律见 [serp-and-traffic-scraping.md](references/serp-and-traffic-scraping.md)（步骤 4 前必读）。

**完成：** 能填短名单，而非「感觉不错」。

### 3. 短名单

最多 **3** 词。交付：

1. 词表行（可用 [keyword-shortlist.md](assets/keyword-shortlist.md)）  
2. 每词：需求一句话 + 量/KD + SERP 摘要 + 灯色建议  
3. 数据缺口列表  

**完成：** 用户看得到建议与缺口；尚未拍板。

### 4. 用户开网页 + 插件复读

对准备拍板的 **1 个**主词，请用户打开：目标国 SERP、前 3–5 竞品、Trends；有 SEO 插件则打开侧栏/SERP 旁指标。

用户说「开好了」后：Agent 用浏览器读**已打开标签**（流量、定价、功能、停留等可见指标），写竞品表：谁、量级感、为何能起来、缺陷、是否同一句话硬刚。

**完成：** 有基于真页的竞品表，不是只凭搜索摘要。

### 5. 场景还原（建议 go 前）

用 YouTube 等**实操向**视频（1–3 条），把任务写成流水线：

`输入 → 用户步骤 → 输出 → 最痛一步 → 现在怎么凑合`

填 [scene-card.md](assets/scene-card.md)。对照竞品：工具省了哪步、仍缺哪步。

**无体感且未写场景卡 → 默认最高灯色 `watch`，不建议 `go` 做完整产品。**  
用户声明「只跑流程、不做产品」→ 归档词表即可。

**完成：** 用户能口述流程；说不清则不 go。

### 6. 灯色与拍板

| 灯色 | 何时 | 下一步 |
|------|------|--------|
| **go** | 场景懂 + SERP 可打 + 付费线索 + 能量化或诚实标缺口 + **窄于头名的唯一承诺** | 最小页/实验（另 skill/项目）；本 skill 停 |
| **watch** | 有希望但场景未懂 / 数略偏 / 竞品密 | 补场景、样张对比或复查日 |
| **narrow** | 需求真、切口错 | 改任务/修饰词，回步骤 2 |
| **reject** | 铁板 SERP / 无付费理由 / 做不了或不愿懂 | 记失败闸门，回找词 |

**分食可以，硬刚不行：** 大站有流量证明需求；产品句子必须错开头名主叙事（更窄人群、更窄任务、补缺陷），禁止「再做一个一样的」。

**完成：** 用户明确四选一；Agent 不代为宣布最终 go。

## 工具路由

| 需要 | 优先 | 缺失时 |
|------|------|--------|
| 真 SERP / 已开页 | 用户 Chrome（browser 类工具） | 说明局限；web 搜索仅作弱补充 |
| 月搜/KD | 免费 KD 页、插件、登录 Overview、API | No data + SERP/Trends 降级 |
| 扩词 | 自动补全、Trends related、扩词网页 | 用户粘贴 |
| 社区人话 | 公开检索；登录态走用户浏览器 | 不伪造「已观察」 |
| 场景 | YouTube 等实操 | 不 go 完整产品 |

实现品牌可换（Ahrefs / SEMrush / AITDK / 其它）；**问题固定**，工具名不写死为唯一合法。

## 不做什么

- 不编造量化数字。  
- 不把 AI 扩词列表当成已验证需求。  
- 不在本 skill 内写完整产品代码或强制卖空气访谈（可另 skill）。  
- 不因已有竞品就放弃整条赛道，也不因有竞品就默认 go。  
- 不把商店整站流量（如 Play/App Store 域名月访）当成单个工具 App 的用户数。

## 完成判据

- 短名单 ≤3，每词有 SERP 摘要与量/KD 字段（真数、线索或 No data）。  
- 灯色建议能说明与参考带、SERP、付费、场景的关系。  
- 若建议 go：存在场景卡（或用户书面确认已懂流程）+ 一句**窄于头名**的产品承诺。  
- 交付物可粘贴进任意项目笔记；不依赖本 skill 仓库外的绝对路径。
