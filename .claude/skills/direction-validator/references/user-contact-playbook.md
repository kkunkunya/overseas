# 找方向时如何接触真人

## 1. 原方法与本项目归纳的边界

赫兹强调先锁定具体人群、场景、痛点，并以真实付款而非口头兴趣验证；赫兹对哥飞直播的整理强调真正进入 Twitter、Facebook、Reddit 等用户社区理解需求。原材料没有规定一套通用冷私信话术。

下面的接触顺序是为保护验证质量形成的项目执行规则，不冒充作者原话。

## 2. 渠道组合：引荐不是必需品

| 渠道 | 最适合验证 | 常见误判 |
|---|---|---|
| SEO 搜索数据 | 是否有人主动表达任务与意图 | 有量等于会付费 |
| Reddit / Facebook 等社区 | 用户原话、流程、替代方案、招募线索 | 点赞等于需求；一次删帖等于无需求 |
| 竞品评论与定价 | 已有购买行为、缺口、切换原因 | 单条差评等于普遍痛点 |
| 访谈 / 付费招募 | 最近一次真实行为、频率、代价、工作流 | “会不会用”这种假设回答等于行动 |
| 小额广告 + Landing Page | 陌生流量的点击、询价、预订或付款 | 点击等于商业闭环 |
| 可信朋友引荐 | 更快建立信任、取得样例和走查 | 没有引荐就无法验证 |

新手默认选 2–3 个互补渠道：一个市场/搜索入口 + 一个用户行为入口 +（必要时）一个冷流量销售实验。不同渠道用于交叉验证，不要求把所有渠道跑完。

## 3. 社区接触顺序

1. **Chrome 登录态观察**：Reddit、X、YouTube、Discord、Facebook 或封闭论坛优先调用 Codex Chrome 插件，复用用户现有登录状态，收集近期问题、评论、替代方案、价格与用户原话。
2. **登录/权限交接**：若页面要求首次登录、加入社区、二次验证或用户权限，停在该页面并请用户完成；用户确认后继续复用同一 Chrome 状态，不换匿名搜索绕过。
3. **检查渠道**：阅读版规、固定帖、账号门槛、研究/推广限制及隐私要求。
4. **上下文回复**：只回复与原帖直接相关的人，先给一个能帮助原问题的观察、资源或追问；只有该 early prototype 确实相关时才自然说明自己做了什么。
5. **征得私聊许可**：公开回复得到回应后，再问能否私聊几个问题。
6. **访谈当前行为**：问上一次怎么完成、频率、耗时、错误、现有付费；不要先问“你会不会用我的产品”。
7. **展示最小承接**：确认问题后再展示概念稿、Landing Page、APP 原型或人工服务，并给出真实价格。
8. **记录行动证据**：屏幕走查、脱敏样例、复用、询价、订金和付款强于点赞与称赞。

Chrome 观察是读取，不自动授权发帖、私信、加入社区或提交表单；这些外部动作仍需用户明确同意。

## 4. 最小公开回复结构

```text
引用原帖的具体问题
→ 给一个与问题直接相关的帮助或观察
→ 自然说明自己由此想到的 idea / 已做出的最小工具（仅在相关时）
→ 问一个当前行为问题
→ 邀请对方自愿继续交流或私聊
```

每条消息针对原帖改写。不要伪造使用经历、批量复制话术、隐藏商业身份、要求未脱敏的订单数据，或在被过滤后反复重发。

## 4.1 评论区的三重用途与后续分发

同一条高质量评论区可按时间分三次使用，但每次的目的不同：

1. **选词 / 文案**：记录用户对任务、对象、失败点和期待结果的自然语言，转成
   候选词、长尾修饰词、Landing Page 表达或访谈追问；
2. **趋势 / 市场语境**：比较同一问题是否在多个相邻内容下反复出现、用户正在用
   什么 workaround、是否有明确的 `why now`。评论数和点赞数只说明互动，不单独
   证明需求或付费；
3. **价值分发**：仅当原讨论仍相关、平台与创作者规则允许、且回复能直接帮助当前
   提问时，回到讨论下补充答案或分享早期测试入口。链接要使用匿名归因参数，以便
   区分来源和内容变体；没有可用观测时先修观测，不扩大触达。

不要自动挖取、群发或在不相关的热门内容下塞链接。评论区提供的是语境和许可边界，
不是联系人名单。

## 5. 把失败归因到正确闸门

| 结果 | 说明 | 不能推出 |
|---|---|---|
| 版规禁止、帖子归档、账号被过滤 | 渠道失败 | 需求不存在 |
| 有曝光但没人回复 | 话题、信任或需求都可能弱 | 一次即可判死刑 |
| 回复但拒绝访谈/样例 | 问题可能不够痛，或信任不足 | 已有购买意愿 |
| 演示当前流程并提供脱敏样例 | 强问题证据 | 一定会付款 |
| 愿意复用、询价、交订金或付款 | 商业证据 | 已找到可规模化流量 |

## 6. 预设接触预算与停止条件

每轮先写明目标人群、渠道、联系上限、观察期限和成功动作。示例：只联系 5–8 位近期公开表达同一问题的人；不回复不追发；若渠道持续过滤则切换获准社区、Facebook 群组、竞品评论线索、付费招募或冷流量页面。可信引荐有则使用，没有就跳过。

渠道不可复现且没有替代入口时，将方向标为 `watch`；不要为了证明需求而继续刷帖。只有合资格用户真正接触方案后仍不使用、不询价、不付款，才把失败归到承接或变现。
